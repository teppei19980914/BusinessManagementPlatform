# 問題修正スキル

> **2026-05-09 改訂**: 「セキュリティ観点別レビュー (auth/injection/xss/secret/dependency)」と
> 「パフォーマンスチェック」をローカル必須項目から外した。代替の運用は CLAUDE.md「コミット前チェック」
> セクションを参照:
> - **セキュリティ**: GitHub Actions `.github/workflows/security.yml` で PR ごとに自動スコア検査 (閾値 90/100)
> - **パフォーマンス**: ユーザリクエストによる都度対応。発見パターンは `docs/knowledge/KDD_PATTERNS.md` に蓄積
>
> 上記レビューエージェント (`auth-reviewer` 等) はユーザが明示的に依頼した場合のみ実行する。

## 手順

1. 問題のレポートや指摘事項を確認する
2. **情報源の選定（必須）** — 調査が必要な場合は CLAUDE.md「情報源の信頼性ルール」に従い、公式ドキュメント・公式リポジトリを最優先で参照する。推測ベースの実装は禁止
3. 該当するソースコードを特定・修正する
4. テストコードを必ず追加・修正する
5. **退行チェック**: 修正した問題と同じパターンが他ファイルにないか `Grep` で検索 + 横展開
6. コミット前チェックを実施（下記）

## 横展開チェック

- 修正した問題と同じパターンが他ファイルにないか検索
- テストコード内で旧文言を検索し全て新文言に修正
- 共通処理の変更は関連する全ファイルに横展開

## デプロイチェック

ローカルで以下を実行し全て成功を確認:

```bash
pnpm lint
pnpm tsc --noEmit
pnpm test
pnpm build
```

## ドキュメント更新

変更内容に応じて該当ドキュメントを更新 (CLAUDE.md「コミット前チェック」§5 のディレクトリ構成を参照):
- 仕様変更 → `docs/specification/`
- 設計変更 → `docs/design/`
- 要件追加 → `docs/business/`
- 運用手順変更 → `docs/operations/`
- KDD ナレッジ → `docs/knowledge/KDD_PATTERNS.md` または `docs/test/E2E_LESSONS.md`
