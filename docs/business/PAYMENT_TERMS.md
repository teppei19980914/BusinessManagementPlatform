# 支払い条件と滞納時の取扱い (Payment Terms)

本ドキュメントは、本サービスの **請求書 / 銀行振込支払いに関する支払い条件と、滞納が発生した場合の対外的なルール** を定義する。

実際の super_admin 手順は [../operations/PAYMENT_DELINQUENCY_SOP.md](../operations/PAYMENT_DELINQUENCY_SOP.md) を参照。本文書は「ユーザに対してどう案内するか」「どこから利用制限・解約に進むか」のルールを規定し、利用規約 / 個別契約の根拠となる。

## 0. 前提と適用範囲

### 0.1 想定スケール (2026-05-09 時点)

- **顧客テナント数**: 数件〜10 件未満 (β / 初期商用フェーズ)
- **滞納件数の想定上限**: 月あたり 1〜2 件程度
- **対応体制**: super_admin が個別対応で十分回せる規模 (自動催促・自動停止は未実装)
- **将来 (50 件超)**: 自動催促メール / 自動 read-only 化を実装する。本文書のしきい値はそのまま自動化に流用できる粒度で記述する。

### 0.2 対象となる支払い方法

`Tenant.paymentMethod` は以下のいずれか:

| 値 | 概要 | 滞納検知の主体 |
|---|---|---|
| `invoice` | 請求書送付 (PDF を `billingContactEmail` 宛にメール送信) | super_admin が入金確認 |
| `bank_transfer` | 銀行振込 (請求書に振込先記載) | super_admin が入金確認 |
| `credit_card` | 後続実装 (PR #1 で UI 上 disabled) | (未実装) |

クレジットカードは v1 では受け付けないため、本文書は `invoice` / `bank_transfer` の 2 方式のみを対象とする。

### 0.3 課金対象プラン

- **Beginner プラン**: 無料のため本文書の対象外 (滞納の概念がない。Beginner 90 日経過の read-only 化は別ロジック / [TENANT_AND_BILLING.md §34.14.4](./TENANT_AND_BILLING.md))
- **Expert / Pro プラン**: 従量課金 (per-API-call) のため、本文書の対象

## 1. 支払い期日と請求サイクル

### 1.1 請求サイクル (2026-05-14 確定: 月末締め + 翌月15日請求書発行 + 翌月25日支払)

| 項目 | 値 |
|---|---|
| 請求対象期間 (締日) | 月初 (UTC 00:00 / JST 09:00) 〜 月末 (UTC 23:59 / JST 翌 1 日 08:59) |
| 請求書発行期限 | **締日翌月の 15 日まで** (super_admin が手動で発行・メール送付) |
| 支払期限 | **締日翌月の 25 日** (請求書 PDF に明記、固定日) |
| 支払い遅延損害金 | 当面は **設定しない** (β フェーズの信頼関係優先) |

**例: 5月利用分**:
- 締日: 5/31
- 請求書発行期限: 6/15
- 支払期限: 6/25

> 商用化後の支払い遅延損害金導入は再検討事項として [docs/roadmap/](../roadmap/) に切り出し。

### 1.2 期日の運用ルール

- **起算日**: 締日 (= 利用月の月末) を基準とし、支払期限は固定で **締日翌月25日**
- **発行遅延の影響**: super_admin の請求書発行が 15日を過ぎた場合でも、原則として **支払期限 (25日) は固定**。社内の発行遅延を顧客の不利益にしない場合は個別判断で延長可
- **休日特例**: 支払期限 (翌月25日) が土日祝に当たる場合、**翌営業日まで延長** (一般的な商習慣)
- **本サイクルの根拠**: 過去の「請求書発行日 + 30 日」運用との置き換え (2026-05-14 改訂)。固定日 (25日) にすることで顧客の経理処理 (社内振込締日) が整い、運営側のキャッシュフローも月次で予測可能になる

### 1.3 入金確認のタイミング

super_admin は **翌月16日〜25日の入金期間中に随時** 銀行口座を確認し入金消込を行う。
**翌月26日朝** に支払期限到来後の未入金テナントを抽出し、滞納フローへ移行する。

詳細手順: [../operations/PAYMENT_DELINQUENCY_SOP.md](../operations/PAYMENT_DELINQUENCY_SOP.md) §0
月次請求業務全体: [../operations/BILLING_MONTHLY_OPERATIONS.md](../operations/BILLING_MONTHLY_OPERATIONS.md)

> 自動消込は未実装。Stripe 連携 (Metered Billing) は v1.x 以降で実装し、その時点で本セクションを更新する ([TENANT_AND_BILLING.md §34.14.8](./TENANT_AND_BILLING.md))。

## 2. 滞納フェーズと対応ルール

支払い期日からの経過日数で 4 フェーズに分け、それぞれで取るアクションと利用制限を定義する。**実際の手順は [SOP](../operations/PAYMENT_DELINQUENCY_SOP.md) を参照**。

### 2.1 全体像

| フェーズ | 経過日数 | 利用制限 | 対外アクション |
|---|---|---|---|
| **0. 期日内** | 〜期日 | なし | 通常運用 |
| **1. 軽度遅延** | 期日 +1 〜 +30 日 | なし (運用継続) | リマインダーメール送信 |
| **2. 重度遅延** | 期日 +31 〜 +60 日 | **read-only モード移行** | 督促メール + 電話 / 担当者直接連絡 |
| **3. 連絡不通** | (任意フェーズ) +14 日連絡途絶 | read-only 維持 | 内容証明郵便の準備 / 法務確認 |
| **4. 回収不能** | 倒産・破産・期日 +90 日以上 | **テナント削除予告 → 削除** | 債権放棄 or 弁護士引き継ぎ |

### 2.2 フェーズ 1: 軽度遅延 (期日 +1〜+30 日)

#### ルール
- **利用制限なし**: 顧客の信頼関係を優先し、業務影響を出さない
- リマインダーメール: 期日 +3 日 / +14 日の **2 回** 送信
- 送信先: `billingContactEmail`
- 文面: 「請求書 No. XXX のお支払いがまだ確認できておりません。お忙しいところ恐れ入りますが、ご確認をお願いいたします」 (穏便)

#### 想定理由
β 顧客は経理サイクルの都合 (月末締め翌々月末払い等) で 30 日程度の遅延は珍しくない。一律で機械的に止めると顧客体験を損なう。

### 2.3 フェーズ 2: 重度遅延 (期日 +31〜+60 日)

#### ルール
- **read-only モード移行**: テナント全体を read-only にし、**新規 API 課金を発生させない**
  - 理由: 滞納が確定的になりつつある状況で、さらに従量課金を積み上げて回収難度を上げないため
- 移行前に **2 営業日の予告メール** を送信 (心理的衝撃を緩和)
- 督促メール (期日 +31 日 / +45 日) と並行して **電話 or 営業担当の直接連絡** を試みる
- 文面: 「お支払いが期日から 30 日を超えて確認できておりません。本日より一時的にサービスを read-only にいたします。お支払いを確認次第、即座に解除いたします」

#### read-only モードの技術的状態
- **読み取り**: 可能 (ログイン / プロジェクト閲覧 / リスク・課題閲覧 / ナレッジ閲覧)
- **書き込み**: 不可 (新規プロジェクト作成 / リスク起票 / コメント投稿 / インポート / API 提案生成すべて 403 / "service suspended due to unpaid invoice")
- **エクスポート**: **可能** (顧客のデータ所有権を尊重し、解約時の引き上げ手段を担保)
- **Beginner 90 日 read-only との違い**: Beginner は永続防止のためのアップセル誘導 ([TENANT_AND_BILLING.md §34.14.4](./TENANT_AND_BILLING.md))、本フェーズは滞納による商業的措置。**両者の挙動は同一だが、根拠と解除条件が異なる** (未入金解消 vs プラン変更)
- **実装状況 (2026-05-14 / PR #372)**: **専用フラグ `Tenant.suspendedAt` 実装済み**。
  super_admin が `/admin/super/tenants/[id]` 画面の「⏸ テナントを停止」ボタン、または
  `POST /api/admin/super/tenants/[id]/suspend { reason }` 経由で実行する。
  停止時に配下の全ユーザの `tokenVersion` が increment され、既存セッションは次リクエストで
  401 SESSION_INVALIDATED → 強制ログアウト。再ログイン後の JWT claim `tenantSuspendedAt` を
  middleware (auth.config.ts) が判定し、write 系 HTTP method を 403 `TENANT_SUSPENDED` で遮断。
  例外パス (`/api/tenants/me` PATCH/DELETE と `/api/tenants/me/self-delete` POST) は引き続き通過するため、
  顧客は支払い後の解除を待たずプラン変更 / セルフ解約で能動的に脱出できる。
  解除は `POST .../resume` で `suspendedAt=null` + `resumedAt=now` をセット + 再度 tokenVersion increment。

### 2.4 フェーズ 3: 連絡不通 (任意フェーズで +14 日連絡途絶)

#### 「連絡不通」の定義
以下の **すべて** に該当した場合、連絡不通フェーズに移行する。

1. メールが 3 通連続で 14 日以内に未返信 (open 確認できない場合は送信のみで判定)
2. 電話 / 営業担当連絡を 2 回試みて応答なし
3. `billingContactEmail` がバウンスする / メールアドレス変更を確認できない

#### ルール
- read-only 状態を維持 (フェーズ 2 から進入した場合)
- **内容証明郵便の準備**: 法人登記簿 (国税庁法人番号公表サイト) の住所に向け、債権額・期日・連絡要請を明記して送付準備
- 法務確認: 顧問弁護士 (まだ未契約の場合は商工会議所の無料相談) に手順確認
- 顧客のデータは **凍結保存** (削除しない)。連絡再開時のデータ消失を防ぐ

#### 内容証明送付の判断基準
- 債権額 ¥10,000 以上: 送付推奨 (郵送費 1,250 円程度の元は取れる)
- 債権額 ¥10,000 未満: 送付スキップ可 (商業的合理性で判断)

### 2.5 フェーズ 4: 回収不能 (倒産 / 期日 +90 日以上)

#### 「回収不能」と判定する条件 (いずれか)
- 顧客の **倒産・破産・廃業** が官報・帝国データバンク・本人通知で確認できた
- 期日 +90 日を超えても入金 / 連絡が一切ない
- 内容証明郵便が「宛所に尋ねあたらず」で返戻された

#### ルール

**倒産・破産の場合**:
- 破産管財人または破産者本人に **債権届出** (破産法 111 条) を提出するか判断
  - 債権額 ¥50,000 以上: 届出推奨
  - 債権額 ¥50,000 未満: 配当見込みが薄いため届出スキップ可 (営業判断)
- データは **30 日後に物理削除** (テナント削除フローに乗せる)
  - 理由: GDPR / 個人情報保護法上、契約終了後の継続保管は最小限にする
  - 削除前に super_admin が CSV エクスポートを取得し、 `docs/operations/legal-archive/` に **5 年間** 保管 (法務上の証拠)

**期日 +90 日超 + 連絡不通の場合**:
- **債権放棄** (損金算入) を会計処理で実施
- テナント削除予告メール (削除 14 日前に送信、メールが届かなくとも形式的に送信) → 14 日後に物理削除
- 削除前に CSV エクスポートを取得し 5 年間保管 (上記と同じ)

#### debt forgiveness (債権放棄) の事務処理
- 法人税法上は損金算入可 (債務者が音信不通かつ回収不能と認定できる場合)
- super_admin は経理担当に「○○年○月期 売掛金 ¥XXX を回収不能として損金処理」と申請

## 3. 利用規約への組み込み

本文書のルールは利用規約 (まだ未策定) に転記して **法的拘束力を持たせる必要がある**。以下の条項として組み込む想定:

- 第 X 条 (支払い): 期日と支払い方法を §1 と同じ条件で規定
- 第 X+1 条 (支払い遅延): フェーズ 2 read-only / フェーズ 4 削除を「弊社の判断で利用を制限・停止できる」と規定
- 第 X+2 条 (データ削除): 解約 / 強制終了時のデータ削除タイミングを §2.5 の 30 日 / 14 日と整合させる
- 第 X+3 条 (損害金 / 利息): 当面 0%、将来は商事法定利率 (年 3%、2026-05-09 時点) を適用予定

> 利用規約の正式策定は **β → 一般リリース移行時** に法務レビュー込みで実施 ([roadmap/RELEASE_PLAN.md](../roadmap/) 参照、未起票なら作業項目に追加)。

## 4. 顧客側のデータ保護

### 4.1 read-only 期間中

- ログイン可能、過去データ閲覧可能、エクスポート可能
- 支払い完了 → super_admin が解除すれば 即座に書き込み再開可能 (操作内容に消失なし)

### 4.2 テナント削除前

削除予告メール送信から **14 日間** は顧客がエクスポートして引き上げる時間として確保する (連絡不通の場合も形式的に確保)。

### 4.3 削除後の保全データ

物理削除後も **以下の情報は 5 年間保管** する。これは商法・税法上の保管義務 (商法 19 条 / 法人税法施行規則 67 条) に基づく:

- 請求書 PDF (発行済すべて)
- ApiCallLog の月次集計 CSV (個別ログは集計後削除)
- 入金消込記録
- 債権放棄処理の根拠資料

保管場所: `docs/operations/legal-archive/YYYY/<tenant-slug>/` (Git 管理外、運営の安全な場所に別途保管)。
