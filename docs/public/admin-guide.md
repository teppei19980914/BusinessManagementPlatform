# テナント管理者 ご利用ガイド (ユーザ管理・監査ログ・権限変更履歴)

テナント管理者は、組織 (テナント) のユーザ・権限・監査を管理できます。本ガイドでは、ユーザ管理・監査ログ・権限変更履歴の各画面を、テナント管理者向けにご説明します。

> プラン・請求・容量の管理は各課金ガイド ([料金プラン](./plan-guide) / [クレジットカード払い](./credit-card-payment-guide) / [データ容量](./db-capacity-billing-guide) / [ファイルストレージ](./file-storage-billing-guide)) を、ユーザ招待の手順は [アカウント追加手順](./account-setup-guide) を参照してください。

## 1. テナント管理者ができること

テナント管理者 (admin) は、自組織内で以下を行えます。

- ユーザの招待・有効化/無効化・削除・ロック解除
- システムロール (管理者 / 一般ユーザ) の変更
- 監査ログ・権限変更履歴の参照
- 顧客マスタの管理 ([プロジェクト ご利用ガイド §7](./project-guide#7-顧客-customer-の管理))
- プラン変更・予算上限・請求・容量の管理
- 外部データの CSV 一括取込 ([CSV 取込手順](./csv-import-guide))

> これらの管理画面 (ユーザ管理 / 監査ログ / 権限変更履歴) は、一般ユーザには表示されません。

## 2. ユーザ管理

`ユーザ管理` 画面 (`/admin/users`) で、組織のユーザを管理します。

### 一覧の列

| 列 | 内容 |
|---|---|
| ユーザ名 | 氏名 |
| メールアドレス | ログイン ID |
| ロール | テナント管理者 / 一般ユーザ |
| ステータス | 招待中 / 有効 / 無効 |
| 認証ロック | 永続ロック / 一時ロック (解除予定) / ログイン失敗回数 / —（ステータスとは別の情報） |
| 前回ログイン | 最後にログインした日時（一度もログインしていない人は「未ログイン」） |
| 作成者 / 作成日時 | 招待した管理者 / 登録日時 |
| 更新者 / 更新日時 | 最後に編集した管理者 / 最終更新日時 |

氏名・メールアドレスで検索でき、各列で並び替えできます。

### アカウントのステータス（招待中 / 有効 / 無効）

- **招待中**: 招待メールを送ってから、本人がパスワードを設定するまでの状態。
- **有効**: 本人がパスワードを設定し、ログインできる状態。
- **無効**: 管理者が利用を停止した状態（退職者など）。
- ※「認証ロック」は連続したログイン失敗に対する**自動の安全装置**で、上のステータスとは別物です（有効な人でも一時的にロックされることがあります）。

### できること

- 新規ユーザの招待（氏名・メール・ロールを指定 → 招待メール送信）
- 招待中ユーザへの **招待メールの再送 / 招待の取り消し**（編集画面の「招待中」欄から。取り消すと確保していた席が空きます。招待取り消しは「招待中」状態のユーザのみが対象です）
- システムロールの変更（管理者 ↔ 一般ユーザ）
- 利用状態の切替（有効化 / 無効化）
- アカウントロックの解除、**リカバリーコードの再発行**（二段階認証を紛失した人の復旧）
- 前回ログイン日時・二段階認証 (MFA) の設定有無の確認
- ユーザの削除（論理削除）

### 席数について（Beginner プラン）

Beginner プランは席数に上限（最大 5 席）があります。席数は **「有効なメンバー + 招待中のメンバー」** で数えます（招待を出した時点で 1 席を予約）。満席のときは新しい招待を出せないため、先に誰かを無効化するか、招待を取り消して席を空けてください。Expert / Pro は席数無制限です。

### 安全のための制約

- **自分自身のロール・利用状態は変更できません** (管理者が誤って自分を締め出すのを防ぐため)。
- システムロールの選択肢に運営者ロール (super_admin) は表示されません (運営専用のため)。
- ロールや利用状態を変更すると、対象ユーザの全セッションが即時無効化されます。

## 3. アカウントのロックと解除

ユーザ管理画面の各ユーザの編集ダイアログで、認証ロックの状態を確認・解除できます。

- **一時ロック**: 短時間に連続でログイン失敗すると一時的にロックされます (一定時間で自動解除)。
- **永続ロック**: 一時ロックが繰り返されると永続ロックになり、テナント管理者の手動解除が必要です。
- **解除**: 編集ダイアログの「ロック解除」で、ログイン失敗回数・ロックをまとめてクリアできます。

> 長期間ログインのないユーザは、セキュリティのため自動的にログインを停止 (ロック) されることがあります。アカウント情報やデータは保持され、管理画面の有効化で復帰できます。

## 4. 監査ログ

`監査ログ` 画面 (`/admin/audit-logs`) では、組織内で行われた操作 (作成・更新・削除 等) の記録を、新しい順に確認できます。

- 列は **日時・操作者・操作・対象・対象名** で、「いつ・誰が・何を・どうした」を追跡できます（各列で並び替え可）。
- 操作（作成 / 更新 / 削除 など）や対象（ナレッジ / リスク / 課題 など）は、画面の表示言語に合わせて表示されます。
- **絞り込み**: 操作・対象・操作者のプルダウン＋キーワード検索で絞り込めます。
- **列幅の調整**: 列の境界をドラッグして幅を変えられます。元に戻すときは表の右上の「列幅をリセット」を押します。
- **表示件数**: 既定で最新 300 件。右上の「表示件数」で 100 / 300 / 1000 / 全件 を切り替えられ、多い場合は 100 件ごとにページ送りされます。
- **対象名**: プロジェクト名やタイトルが分かる場合に表示します（振り返り・見積など名前を持たないものは「—」）。
- **リンク・ファイルの添付/削除**: 「リンク追加 / ファイル添付 / リンク削除 / ファイル削除」と表示され、「対象」には**どの画面（リスク・課題・ナレッジ・振り返り・メモ等）で行われたか**が出ます（リンクやファイルの内容そのものは記録しません）。
- 監査ログは記録専用で、後から書き換えられない設計です (証跡として信頼できます)。

**記録される範囲**: プロジェクト・タスク・リスク・課題・ナレッジ・振り返り・ステークホルダー・見積・顧客・コメント・メモ・メンバー・ユーザといった**業務データの作成・更新・削除**と、**リンク・ファイルの添付・削除**が対象です。
次のものはこの画面には表示されません: ①閲覧・検索・エクスポート（見ただけの操作は記録しません）②ログイン・二段階認証・パスワード変更などの**認証イベント**（最終ログインはユーザ管理の「前回ログイン」で確認できます）③**ロールの変更**は「権限変更履歴」画面で詳しく追えます。

## 5. 権限変更履歴

`権限変更履歴` 画面 (`/admin/role-changes`) では、システムロール・プロジェクトロールの変更を専用に追跡できます。

| 列 | 内容 |
|---|---|
| 日時 | 変更日時 |
| 変更者 | 操作した管理者 |
| 対象ユーザ | 変更された人 |
| 種別 | システムロール / プロジェクトロール |
| 変更前 / 変更後 | ロールの遷移（テナント管理者 / 一般ユーザ / PM/TL / メンバー 等） |
| 理由 | 任意の記録 |

**記録される内容**: システムロールの変更（テナント管理者⇄一般ユーザ）、ユーザの招待時の初期ロール、**アカウントの有効化・無効化**、ユーザの削除、プロジェクトメンバーの追加・ロール変更・解除が記録されます（変更後が「有効／無効／削除／解除」と表示されることがあります）。

監査ログと同じ操作感で使えます。
- **絞り込み**: 変更者・対象ユーザ・種別のプルダウン＋キーワード検索。各列で並び替えも可。
- **列幅の調整**: 列の境界をドラッグ。表の右上の「列幅をリセット」で初期幅に戻せます。
- **表示件数**: 既定 最新 300 件。右上の「表示件数」で 100 / 300 / 1000 / 全件 を切り替えられ、多い場合は 100 件ごとにページ送りされます。

## 6. FAQ

### Q1. 一般ユーザにユーザ管理を任せられますか?

**A.** いいえ。ユーザ管理・監査ログ・権限変更履歴はテナント管理者のみが利用できます。管理を任せたい人は、その人のシステムロールを「テナント管理者」に変更してください。

### Q2. 自分のロールを変更できません。

**A.** 仕様です。自分自身のロール・利用状態は変更できません (管理者不在や自己昇格を防ぐため)。別の管理者に変更を依頼してください。

### Q3. ユーザを削除すると、その人のデータも消えますか?

**A.** 作成されたナレッジ・タスク等のデータは組織内に残ります。削除されたユーザはログインできなくなります。

### Q4. 監査ログは改ざんされませんか?

**A.** 監査ログは記録専用で、後から書き換えられない設計です。操作の証跡として信頼できます。
