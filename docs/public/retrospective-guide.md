# 振り返り ご利用ガイド

振り返りは、プロジェクト完了後の **総括 (良かった点 / 問題点 / 改善)** を記録し、次の案件につなぐための資産です。本ガイドでは、一覧の見方・入力項目・確定までの流れ・権限を、すべての利用者様向けにご説明します。

## 1. 振り返りとは

プロジェクトが完了したときに、「計画と実績の差」「良かった点」「問題点」「次回への改善」を記録します。「横展開したい知見」に書いた内容を元に [ナレッジ](./knowledge-guide) を作成すると、次のプロジェクトの企画・見積もり・計画に活かせます。

---

## 2. どこで使うか

- **プロジェクト配下** (プロジェクト詳細 →「振り返り」タブ): そのプロジェクトの振り返りを作成・確定します。
- **横断一覧** (`全振り返り` ナビ): テナント内の公開振り返りを横断して閲覧・検索できます。

> 横断一覧では、自分が参加していないプロジェクトの名称は伏せられて表示されます (プライバシー保護)。

## 4. 入力項目

> **必須欄の見方** (2026-06-19 v1.3.0「軽量入力」): **○** = 常に必須／**公開** = 「公開」にするときのみ必須（下書きのままなら任意で、まずは気軽に保存できます）／**×** = 任意。実施日・担当者は公開するときでも任意です。

| 項目 | 必須 | 備考 |
|---|---|---|
| 実施日 | × | 日付 (「今日」「削除」ボタンあり)。未入力でも当日が自動で入ります |
| 計画総括 | 公開 | 2000 文字以内 |
| 実績総括 | 公開 | 2000 文字以内 |
| 良かった点 | 公開 | 3000 文字以内 |
| 問題点 | 公開 | 3000 文字以内 |
| 見積差分要因 | × | 3000 文字以内 |
| スケジュール差分要因 | × | 3000 文字以内 |
| 品質面課題 | × | 3000 文字以内 |
| リスク対応評価 | × | 3000 文字以内 |
| 次回改善事項 | 公開 | 3000 文字以内 |
| 横展開したい知見 | × | 3000 文字以内 |
| 振り返りコメント | × | コメント形式 |

## 5. 作成から確定までの流れ

1. **作成** — 振り返りはプロジェクトのステータスに関係なく作成できます (通常は実行中の終盤〜案件の締めで作成します)。
2. **記入** — 計画/実績総括・良かった点・問題点・次回改善事項・横展開したい知見などを記入します。
3. **確定** — 内容が固まったら「確定」します。
4. **ナレッジへの展開 (任意)** — 「横展開したい知見」に書いた内容を元に、手動で新しい [ナレッジ](./knowledge-guide) を作成すると、次の案件の提案エンジンに活きます。作成したナレッジは [関連資産](./asset-navigation-guide) 機能でこの振り返りとリンクしておくと、後から辿りやすくなります。

> プロジェクトのステータスを「クローズ」にすると、そのプロジェクトは読み取り専用になり、振り返りの作成・編集もできなくなります。振り返りは**クローズの前に**作成・確定してください。

---

## 6. 公開範囲

振り返りにも公開範囲 (下書き / 公開) があります。公開にすると提案エンジンの候補になり、未来の類似案件で「過去の振り返りで挙がった改善点」として提示されます。下書きのままなら索引化・課金は発生しません (詳細: [しくみ・用語ガイド §3](./concepts-guide#3-公開範囲-visibility-のしくみ))。

## 7. 権限

| 操作 | 管理者 | PM/TL | メンバー | 閲覧者 |
|---|:--:|:--:|:--:|:--:|
| 内容を見る | ○ | ○ | ○ | ○ |
| 新規作成 | ○ | ○ | × | × |
| 編集 | ○ | ○ | × | × |
| コメント投稿 | ○ | ○ | ○ | × |
| 確定 | ○ | ○ | × | × |

> 振り返り本体の作成・編集・確定は PM/TL 以上が行います。メンバーはコメントで参加できます。

## 8. FAQ

### Q1. 振り返りはいつ作成できますか?

**A.** プロジェクトのステータスに関わらず作成できます（通常は実行中の終盤〜案件の締めで作成します）。ただしプロジェクトを「クローズ」にすると読み取り専用になり、振り返りの作成・編集はできなくなるため、**クローズの前に**作成・確定してください。

### Q2. メンバーですが振り返りを作成できません。

**A.** 振り返り本体の作成・編集・確定は PM/TL 以上が行います。メンバーは振り返りコメントで意見を残せます。

### Q3. 振り返りで挙げた改善点を次の案件で見られますか?

**A.** 公開した振り返りは提案エンジンの候補になり、類似する新規プロジェクトで「過去の振り返りで挙がった問題・改善」として自動提示されます。

### Q4. 公開した振り返りをメンバーに知らせるには? (v1.5.0)

**A.** 振り返りが「公開」状態のとき、詳細ダイアログに **「共有する」** ボタンが表示されます。クリックするとテナントメンバーを複数選択できるダイアログが開き、確定するとベル通知が送られます。通知を受け取ったメンバーがベルアイコンをクリックすると、その振り返りの詳細画面に直接飛べます。下書き状態では「共有する」ボタンは表示されません。

### Q5. コメントはいつでも投稿できますか? (v1.5.0)

**A.** コメント欄は「**公開**」状態の振り返りにのみ表示されます。下書きの振り返りにはコメント欄が表示されません。これは、下書き状態でコメント内に @メンション を使うと、通知先のメンバーがリンクをクリックしたときに画面が表示されない問題を防ぐための仕様です。

## 補足: 一覧の「上書きインポート」で削除候補を確認する方法

振り返り一覧の「**インポート**」ボタンからCSVを再取り込みする際、プレビュー画面で **「削除候補の扱い」** を選択できます。「**削除: CSV にない振り返りを論理削除**」を選んだ場合のみ、その直下に **「削除候補 (N 件)」** という折りたたみ欄が表示されます。クリックすると対象の一覧が展開されます（デフォルトは閉じた状態）。

> state が `draft` (下書き) 以外の振り返りが削除候補に含まれると赤いエラーになり、実行がブロックされます。
