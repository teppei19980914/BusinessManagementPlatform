# タスク・WBS ご利用ガイド

WBS / タスク管理は、プロジェクトを作業項目に分解し、担当・予定・進捗を管理する中核機能です。本ガイドでは、一覧の見方・入力項目・一括操作・CSV での編集を、すべての利用者様向けにご説明します。

> プロジェクトの状態によって操作できる範囲が変わります ([プロジェクト ご利用ガイド §5](./project-guide#5-状態ごとにできることできないこと))。スケジュールの時系列表示・担当者別の直近確認は [進捗確認 ご利用ガイド](./gantt-guide) を参照してください。

## 1. WBS とタスクの考え方

WBS (Work Breakdown Structure) は、プロジェクトの作業を **階層構造** で分解したものです。大きな作業 (ワークパッケージ) の下に、実作業のタスクをぶら下げて管理します。各タスクには担当者・予定日・予定工数・進捗を設定します。

---

## 2. 一覧画面の列

| 列 | 内容 |
|---|---|
| WBS 番号 | 階層番号 |
| タスク名 | タスク名称 |
| 親タスク | 上位タスク |
| 区分 | 工程区分 |
| 担当者 | 1 名 (WP は配下 ACT の担当者を集約表示。2 名以上の異なる担当者がいる場合は「田中 +N」形式) |
| 開始予定日 / 終了予定日 | 計画日 |
| 実績開始日 / 実績終了日 | 実績日 (担当者が入力) |
| 予定工数 | 数値 |
| ステータス | 未着手 / 進行中 / 完了 / 保留 |
| 進捗率 | 0〜100% |
| 実績工数 | 累積実績 |
| 関連リスク件数 | 件数 |
| 更新日時 | 最終更新 |

> 「ID を表示」トグルを ON にすると、先頭に各タスクの ID 列が表示されます (CSV 上書きインポート用)。列幅はドラッグで調整できます。

## 3. 入力項目

| 項目 | 必須 | 備考 |
|---|---|---|
| 親タスク | × | 指定なしでルート。WP 数が多いときは入力欄に名前を入力して絞り込める |
| タスク名 | ○ | 100 文字以内 |
| タスク内容 | × | 2000 文字以内 |
| 区分 | ○ | 選択式 |
| 担当者 | ○ | 単一選択 |
| 開始予定日 / 終了予定日 | ○ | 日付 (PM/TL が編集) |
| 実績開始日 / 実績終了日 | × | 日付 (担当者が編集) |
| 実績工数 (人時) | 完了時は必須 | 数値 (担当者が編集。未着手では入力不可)。**ステータスを「完了」にするときは 0 より大きい値が必須** (単体・一括とも)。稼働分析サブタブの「消化工数」「工数効率」に使用 |
| 予定工数 | ○ | 数値 (PM/TL が編集) |
| 優先度 | × | 低 / 中 / 高 |
| ステータス | ○ | 担当者も編集可 |
| 進捗率 | ○ | 0〜100 (担当者も編集可) |
| 関連見積項目 / ナレッジ / リスク | × | 複数紐付け可 |
| タスク内容（説明）/ 備考 | × | アクティビティのみ。説明 2000 文字 / 備考 1000 文字以内 |

> 日付欄には「今日」「削除」ボタンが付いています。**進捗率を 100% にすると自動的にステータスが「完了」**になります (逆に「完了」にすると進捗率が 100% に補正されます)。

### 「タスク内容（説明）」と「備考」

アクティビティ（実作業のタスク）には、自由記述の欄が 2 つあります。作業パッケージ（WP）は子の集約ノードのため、これらの欄は表示されません。

- **タスク内容（説明）**: そのタスクで具体的に何をするか（手順・成果物・確認観点など）。
- **備考**: それ以外の補足メモ（関連資料の URL・引き継ぎ・注意事項など）。

どちらも作成・編集ダイアログで入力でき、入力欄の上の **「プレビュー」** ボタンで表示イメージを確認できます（編集時は「差分」で変更前との違いも見られます）。

> **URL は自動でリンクになります**: 本文に `https://…` / `http://…` で始まる URL を書いて保存すると、表示時に自動でクリックできるリンク（新しいタブで開く）になります。日本語の直後に続けて書いても URL の部分だけがリンクになります（例: 「`https://example.com/login`にアクセス」→ リンクは `https://example.com/login` まで）。この自動リンクは、タスクの説明・備考だけでなく、ナレッジ・リスク・課題・振り返り・プロジェクト概要・メモ・顧客の備考・コメントなど各画面の本文欄で共通の挙動です。

## 4. 進捗・実績の更新

- **計画情報** (タスク名・担当・予定日・予定工数など) は **PM/TL・管理者** が編集します。
- **実績情報** (ステータス・進捗率・実績日) は **担当者本人** が更新できます (役割を問わず、自分の担当タスクのみ)。
- 自分の担当タスクは [マイタスク ご利用ガイド](./my-tasks-guide) からまとめて更新するのが便利です。

## 5. 一括操作 (一括編集・複製)

WBS 一覧でタスクにチェックを入れると、まとめて操作できます (PM/TL・管理者のみ)。

- **一括編集 (計画系)**: 担当者・優先度・予定日程・予定工数をまとめて変更。件数上限なし — 大規模 WBS (600 件以上) でもまとめて更新できます
- **一括実績更新**: ステータス・進捗率・実績日程をまとめて更新 (自分の担当タスクのみ)。件数上限なし
- **一括複製**: 選択したタスクを、指定の親の下に階層を保ったまま複製。名称が重複する場合は「(コピー)」が付き、実績情報 (進捗・実績日) はリセットされます (上限 100 件)

## 6. CSV でのエクスポート・上書きインポート

WBS を Excel で編集して取り込む「往復編集」ができます (PM/TL・管理者のみ)。

### エクスポート

タスク一覧から CSV をダウンロードできます。新形式では **ID / 種別 (WP/ACT) / 名称 / レベル / 予定開始日 / 予定終了日 / 予定工数 / 土日祝日を含める** の 8 列が出力されます。

### 上書きインポート (同期)

ダウンロードした CSV を Excel で編集して取り込むと、ID で既存タスクと突き合わせて更新します (ID が空の行は新規作成)。

- 取込前に **プレビュー (dry-run)** が必ず表示され、「追加 / 更新 / 削除候補 / 警告 / エラー」の件数と差分を確認できます。実際の取込はその後に実行します。
- プレビュー画面には「**削除候補の扱い**」という選択肢があります。「**削除: CSV にないタスクを論理削除**」を選んだ場合のみ、その直下に「削除候補 (N 件)」というアコーディオンが表示されます。クリックすると対象タスクの一覧が展開されます (デフォルト閉じ)。
- 進捗のあるタスクが削除候補になった場合は赤いエラーで警告され、「削除」モードでは実行がブロックされます。
- ヘッダー (列名・列順) が一致しない場合や、必須列が空の場合はブロックされます。
- **同じ WP の下に同じ名前のタスクを複数置いても取り込めます** (例: 週内に繰り返す「SC午後1問(読む練習)」など)。プレビューでは「同名がある」旨の**警告**が出ますが、そのまま取込できます (それぞれ別タスクとして作成されます)。
- **件数が多くても安定して取り込めます**。確定実行の内部処理をまとめて行うよう改善したため、追加・更新が多い大きな WBS でも短時間で完了します (以前は更新が多いと途中で時間切れになることがありました)。件数が多い場合 (目安 300 行超) は「処理に時間がかかる場合がある」旨の案内が表示されますが、そのまま実行できます。**1 回の取込で扱える上限は 2,000 行**です (これを超える場合は分割して取り込んでください)。
- **万一エラーで取り込みきれなかった場合は、同じ CSV をもう一度取り込めば安全に最後まで反映されます**。ID で既存タスクと突き合わせるため、すでに反映済みの行は「変更なし」として扱われ、二重には作られません (ID が空の新規行だけは再度新規作成される点にご注意ください)。
- 他の人が同時に編集していた場合は検出され、安全のため中断されます。

> このほか、別プロジェクトへ雛形を流用する「WBS テンプレート」機能 (担当者をリセットして出力) もあります。

## 7. カンバンビュー

WBS 管理画面には「**ツリービュー (階層構造)**」と「**カンバンビュー**」の 2 つの表示形式があり、画面右上のフィルターエリアにあるトグルボタンでいつでも切り替えられます。

### 切替方法

フィルターエリアの右端にある「**ツリービュー / カンバンビュー**」ボタンをクリックするだけです。選択したビューはブラウザのセッション中に記憶されるため、ページを更新しても維持されます。

> カンバンビューはパソコン画面のみ対応しています。スマートフォン・タブレットでは引き続きカード形式で表示されます。

### グリッドの見方

カンバンビューでは横軸が「**全暦日（土日・祝日を含む）**」、縦軸が「担当者」のグリッドになります。ガントチャートと同じく土日祝もカレンダー列として表示され、各マスに担当するタスクの付箋が表示されます。

**列の色分け（ガントと共通）:**

| 列の種類 | ヘッダー色 |
|---|---|
| 土曜日 | 青い背景 |
| 日曜日・祝日 | 赤い背景（祝日はヘッダーに祝日名も表示） |
| 今日 | 強調表示（青緑系）。初回表示時は今日の列が左端にスクロールされます |
| 平日 | 通常（色なし） |

**セルの状態:**

- **開始予定日または終了予定日が未設定のタスク**は最下部の「未スケジュール」行にまとめて表示されます。
- セルの背景が**黄色**になっているときは、1 日の工数合計が 7 時間以上です。
- セルの背景が**赤**になっているときは、1 日の工数合計が 8 時間以上です（過負荷の可能性）。

### 付箋の読み方

付箋の高さは、その日に割り振られた予定工数に比例します（8 時間分が最大の高さ）。付箋が縦に長いほど、その日に多くの工数が見込まれています。

付箋の上にマウスカーソルを合わせると、以下の詳細情報がポップアップで表示されます。

| 情報 | 内容 |
|---|---|
| ワークパッケージ名 | そのタスクが属する WP の名前 |
| 担当者 | 担当メンバー名 |
| ステータス | 現在の状況（未着手 / 進行中 / 完了など） |
| 期間 | 予定開始日〜予定終了日 |
| 総予定工数 | タスク全体の予定工数（h） |
| 日次工数 (推定) | 総予定工数を稼働日数で割った 1 日あたりの値。「土日祝日を含める」設定によって計算方法が変わります |

> 日次工数の計算方法はタスクの「土日祝日を含める」設定によって異なります。
> - **土日祝日を含めない（デフォルト）**: 平日のみを稼働日として均等割り（例: 金〜月 4h → 金 2h・月 2h、土日は付箋なし）
> - **土日祝日を含める**: 全暦日で均等割り（例: 金〜月 4h → 各 1h、土日にも付箋が表示されます）

### 付箋のクリック・チェックボックス操作

- 付箋をクリックすると、通常の**編集ダイアログ**が開きます（ツリービューと同じダイアログです）。
- 付箋右上のチェックボックスにチェックを入れると、複数タスクを選択して**一括操作**が行えます（ツリービューと同じ機能です）。

### 付箋のドラッグ&ドロップ（管理者・PM/TL のみ）

日程設定済みの付箋を別の列（日付）または別の担当者行へドラッグ&ドロップすることで、タスクの**開始予定日・終了予定日・担当者**をその場で変更できます。

| 操作 | 結果 |
|---|---|
| 付箋を別の日付列へドロップ | 開始予定日・終了予定日が差分日数だけシフト（例: 2 日後へ移動 → start/end それぞれ +2 日） |
| 付箋を別の担当者行へドロップ | 担当者が変更される（日付の変更と組み合わせ可） |
| 複数日にまたがるタスクの付箋をドロップ | 全列の付箋が連動してシフト（期間を保ったまま移動） |

**注意事項:**

- **未スケジュール行（日付なし）の付箋はドラッグ不可**です。先に編集ダイアログで日程を設定してください。
- 未スケジュール行へのドロップも受け付けません（日付なしへはシフト計算できません）。
- **「土日祝日を含める」がオフのタスク**を土日・祝日の列にドロップしようとすると、エラートーストが表示されて移動しません（単日タスクの場合）。複数日タスクの場合は開始日・終了日が自動的に直前・直後の平日に補正されます。
- ドロップ後は自動的に画面が更新されます。失敗した場合はエラートーストが表示されます。

## 9. FAQ

### Q1. メンバーですがタスクを新規作成できません。

**A.** タスクの作成・計画情報の編集は PM/TL・管理者が行います。メンバーは自分の担当タスクの進捗・実績を更新できます。

### Q2. 進捗率を 100% にしたらステータスが勝手に「完了」になりました。

**A.** 仕様です。「進捗 100% = 完了」「完了 = 進捗 100%」を双方向で整合させ、矛盾した組み合わせを防いでいます。

### Q3. CSV で取り込んだら一部のタスクが消えそうと警告されました。

**A.** CSV に含まれていないタスクは「削除候補」として検出されます。プレビューのサマリ欄に件数が表示されます。実際にそれらを削除するかどうかは「削除候補の扱い」ラジオボタンで選べます。「**削除: CSV にないタスクを論理削除**」を選んだ場合のみ、削除候補の一覧が折りたたみ形式で表示されます (クリックで展開)。進捗のあるタスクが削除候補になっている場合は赤いエラーが出て実行がブロックされます。意図しない削除でないか一覧を確認してから実行してください。

### Q4. タスクの編集や作成ができない状態があります。

**A.** プロジェクトの状態 (計画中・実行中など) によって操作範囲が変わります。完了以降は原則編集できません。詳細は [プロジェクト ご利用ガイド §5](./project-guide#5-状態ごとにできることできないこと)。

### Q5. 同じ WP の下に同じ名前のタスクを複数取り込めますか？

**A.** はい、取り込めます。たとえば毎週繰り返す「SC午後1問(読む練習)」のような同名タスクを同じ週 (WP) の下に複数置けます。プレビューでは「同名がある」旨の**警告**が出ますが、そのまま取込でき、それぞれ別タスクとして作成されます。画面からの手動作成・編集でも同名が使えます。

### Q6. 行数の多い WBS を取り込むとエラーになりますか？

**A.** 大きな WBS でも安定して取り込めるよう改善しています。確定実行の内部処理をまとめて行うようにしたため、**追加・更新が多い WBS でも短時間で完了**します (以前は更新の多い WBS で途中で時間切れになることがありました)。件数が多い場合 (目安 300 行超) は「処理に時間がかかる場合がある」旨の案内が表示されますが、そのまま取込できます。**1 回で取り込める上限は 2,000 行**です。これを超える場合は CSV を分割して取り込んでください。

### Q7. 取り込みが途中で失敗したらデータはどうなりますか？ もう一度やり直しても大丈夫ですか？

**A.** はい、**同じ CSV をもう一度取り込めば安全に最後まで反映されます**。取り込みは各行の ID で既存タスクと突き合わせるため、すでに反映済みの行は「変更なし」として扱われ、二重には作られません。万一、通信や時間切れで一部しか反映されなかった場合でも、同じ CSV を再度取り込めば残りが反映され、最終的に CSV どおりの状態に揃います。

> 注意: **ID が空の行 (新規作成)** だけは、再取込のたびに新しいタスクとして作られます。一度作成した行を再取込したい場合は、エクスポートで採番された ID を CSV に入れてから取り込んでください。

### Q8. タスクの工数を土日・祝日にも割り振りたいのですが。

**A.** タスクの作成・編集ダイアログに「**土日祝日を含める**」チェックボックスがあります（アクティビティタスクのみ）。チェックを入れると土日・祝日も稼働日として扱い、工数を全暦日で均等割りします。チェックなし（デフォルト）は平日のみが稼働日です。ダイアログには「稼働日数: X 日」も表示されるため、設定に応じた稼働日数を確認しながら入力できます。

### Q9. WBS の進捗を予定と比べてグラフで見られますか？

**A.** はい。プロジェクト詳細の **「参考情報」→「稼働分析」サブタブ** に 2 つのグラフがあります。**① WBS 予実カーブ**は、予定と実績の進捗を折れ線で比べ、遅れ／先行を見ます。**② 担当者別 週次 消化工数**は、完了タスクの実績工数（人時）を週ごと・担当者別に積み上げ、誰がどれだけの作業量をこなしたかと、工数効率（予定工数 ÷ 実績工数）を見ます。②を使うには、担当者が実績入力で「実績工数」を入れてください。稼働分析は **PM/PL・テナント管理者のみ** 表示されます（完了したプロジェクトでも閲覧可）。詳しくは [稼働分析 ご利用ガイド](./analysis-guide) を参照してください。

### Q9. 全タスクが完了したことに気づく仕組みはありますか？

**A.** はい。プロジェクト内の全アクティビティが「完了」または「保留」だけになると、プロジェクト詳細画面の上部に振り返り実施を促すお知らせが表示されます (そのプロジェクトの PM/TL のみ)。詳しくは [資産導線 ご利用ガイド §4](./asset-navigation-guide#4-wbs完了バナー) を参照してください。

### Q10. ワークパッケージ (WP) のステータスはどのように自動判定されますか？

**A.** WP のステータスは、配下のアクティビティのステータスから自動で決まります。優先順位は次のとおりです。

| 配下 ACT の状況 | WP のステータス |
|---|---|
| 全員「完了」 | 完了 |
| 「実施中」が 1 件以上 | 進行中 |
| 「保留」が 1 件以上（実施中なし） | **保留** |
| 一部「完了」・残りが「未着手」 | 進行中 |
| 全員「未着手」 | 未着手 |

例: ACT が「完了 2 件・保留 1 件」の場合、WP は「**保留**」と表示されます。実施中が 1 件でもあれば「進行中」が優先されます (v1.3.0 で修正)。

### Q11. WBS でワークパッケージの担当者欄に「田中 +2」と表示されています。これは何ですか？

**A.** WP（作業パッケージ）の担当者は、**直下の子タスク（1 階層のみ）** の担当者を自動で集約して表示します。

| 直下の子タスクの状態 | WP に表示される担当者 |
|---|---|
| 子が 0 件 | − |
| 全員が同じ担当者 | その担当者名 (1 名表示) |
| **2 名以上の異なる担当者がいる** | **「田中 +2」** のように先頭の担当者名 ＋ 残り人数を表示 |
| 全員未アサイン | − |
| 一部のみアサイン | − (混在扱い) |

集約は **1 階層のみ** です。最上位 WP は直下の子 WP を、子 WP は直下の孫 WP や ACT を集約します。「田中 +2」は WBS 一覧とガントチャートの担当者列で共通して表示されます (v1.5.0)。

**ZIP インポート後も** 同じロジックで担当者集約が自動的に再計算されるため、インポート直後から正しく表示されます。

誰が担当しているか詳しく確認する場合は、WP を展開して個々のアクティビティをご確認ください。
