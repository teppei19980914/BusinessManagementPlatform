# プロジェクト作成手順

「たすきば Knowledge Relay」で新しいプロジェクトを作成し、過去資産を提案エンジンで活用するための **手順書** です。エンジニアの方でなくてもお読みいただけるよう、専門用語をできるだけ避けて記載しています。

---

## はじめに：本書で扱う 3 つのポイント

たすきばのプロジェクト管理では、次の 3 つを押さえると効率よくお使いいただけます。

| ポイント | 内容 |
| --- | --- |
| **準備①** | プロジェクトを作成する前に、**顧客データの登録が必要** です |
| **準備②** | 過去資産（ナレッジ・課題・振り返り）を **「公開」状態** にすることで、他プロジェクトの提案候補に乗ります |
| **設計思想** | **自分のプロジェクト内で作成した資産は、そのプロジェクト自身の提案には表示されません**（過去案件から学ぶための設計のため） |

> たすきばの提案エンジンは「**過去のプロジェクトから現在のプロジェクトへ知見をつなぐ**」ことを目的に設計されています。同じプロジェクト内の資産は「現在持っているもの」として扱われ、提案対象から除かれます。新規プロジェクトを開く際に、別案件で蓄積された知見が自動で並ぶ —— これがたすきばの中核機能です。

---

## 全体の流れ

```
[ステップ 1] 顧客データを登録する
    プロジェクトを紐付ける顧客（受注先・社内部署など）を事前登録
        ↓
[ステップ 2] プロジェクトを作成する
    プロジェクト名・顧客・目的・背景・スコープなどを入力
        ↓
[ステップ 3] メンバーを追加する
    プロジェクトに参加するチームメンバーを招待
        ↓
[ステップ 4] 資産（ナレッジ・課題・振り返り）を「公開」する
    将来の別案件で参照されるよう、公開範囲を「全メンバー」に設定
        ↓
[ステップ 5] 別の新規プロジェクトを開いたとき
    過去の公開済み資産が提案エンジンに自動で並ぶ
```

---

## ステップ 1：顧客データを登録する（必須・最初の 1 回のみ）

### 対象者
プロジェクトを作成する権限を持つ方（**テナント管理者** または **PM/TL ロール** のメンバー）。

### なぜ必要か
プロジェクト作成画面の「顧客」欄は、**事前に登録された顧客から選択する形式** になっています。顧客が 1 件も登録されていない状態では、プロジェクトを作成できません。

### 手順

#### ① 全顧客管理画面を開く

画面上部のメニューから **「全顧客管理」** をクリックしてください。

#### ② 顧客を新規登録する

画面右上の **「新規顧客」** ボタンをクリックし、次の項目を入力します。

| 項目 | 説明 |
| --- | --- |
| **顧客名** | 必須。例：「株式会社サンプル」「営業部」「自社（社内案件用）」 |
| 業界 | 任意。提案エンジンの精度向上のため入力推奨 |
| 規模 | 任意（従業員数や事業規模等） |
| 備考 | 任意。注意事項・契約条件などを自由に記載 |

> **社内案件・個人プロジェクトの場合は？**
> 顧客名に「自社」「個人」など、案件分類に使える名称を登録してご利用ください。後から編集も可能です。

#### ③ 保存する

「保存」をクリックすると顧客一覧に追加され、以降のプロジェクト作成画面で選択できるようになります。

---

## ステップ 2：プロジェクトを作成する

### 対象者
**テナント管理者** または **PM/TL ロール** のメンバー。

### 手順

#### ① プロジェクト一覧画面を開く

画面上部のメニューから **「全プロジェクト」** をクリック → 右上の **「新規プロジェクト」** ボタンをクリック。

#### ② プロジェクト情報を入力する

「新規プロジェクト作成」ダイアログが開きます。次の項目を入力します。

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| **プロジェクト名** | ✅ | 例：「2026 年度上期 新製品 A 開発」「○○社向け業務改善案件」 |
| **顧客** | ✅ | ステップ 1 で登録した顧客から選択 |
| **目的** | ✅ | このプロジェクトで達成したいゴール |
| **背景** | ✅ | プロジェクト発足の背景・経緯 |
| **スコープ** | ✅ | 対象範囲・対象外範囲 |
| **開発方式** | ✅ | スクラッチ開発／パッケージ導入／クラウド移行 など |
| **契約形態** | 任意 | 請負／準委任／社内案件 など |
| **開始予定日** | ✅ | プロジェクト開始予定日 |
| **終了予定日** | ✅ | プロジェクト終了予定日 |
| **タグ** | 任意・**推奨** | 「Web 開発」「金融」「Excel 移行」など複数指定可。**提案エンジンの精度に直結** |

> **タグはなぜ重要か？**
> 提案エンジンは「タグの一致度」「本文の言葉の一致度」「意味の近さ」の 3 軸で過去資産を探します。タグを丁寧に入力することで、過去案件のナレッジ・課題が高精度で候補に並びやすくなります。

#### ③ 「作成」をクリックする

保存と同時に、たすきばの提案エンジンが起動し、**過去の類似プロジェクトのナレッジ・課題候補** を自動抽出します。

#### ④ 「類似ナレッジ／過去課題の提案」ダイアログを確認

新規プロジェクト作成直後に、過去資産の提案ダイアログが表示されます。役立ちそうな候補があれば「このプロジェクトに紐付け」をクリックして本プロジェクトの参考資産として登録できます。後から「参考」タブで再確認することも可能です。

---

## ステップ 3：メンバーを追加する

### 対象者
テナント管理者または PM/TL。

### 手順

#### ① プロジェクトを開き「メンバー」タブをクリック

プロジェクト詳細画面の上部タブに **「メンバー」** があります。

#### ② 「メンバー追加」をクリック

| 項目 | 説明 |
| --- | --- |
| **ユーザ** | テナント内の既存メンバーから選択（事前にアカウント追加手順でメンバー招待が必要） |
| **ロール** | `PM/TL`（プロジェクト管理者）／ `member`（一般メンバー）／ `viewer`（閲覧のみ） |

> プロジェクトを作成した方は、自動的に **PM/TL** ロールとして追加されます。
> プロジェクト作成者自身がナレッジを作成・編集するためにも、追加で行う操作は不要です。

---

## ステップ 4：資産を「公開」する（提案エンジン活用の鍵）

### なぜ重要か

ナレッジ・リスク・課題・振り返りには **「公開範囲」** があります。これが提案エンジンに **掲載されるかどうかを直接決定** します。

| 公開範囲 | 提案エンジンへの掲載 | 想定用途 |
| --- | --- | --- |
| **下書き** | ❌ 掲載されない | 作成途中・未推敲の状態 |
| **自分のみ** | ❌ 掲載されない | 個人メモ・自分専用の備忘 |
| **全メンバー（公開）** | ✅ **掲載される** | チーム・組織全体で活用したい知見 |

> 「下書き」「自分のみ」の状態では、本サービスは **AI 処理（embedding 生成）を行いません**。これは無駄な AI 利用コストを抑えるための仕様です。**「全メンバー」に変更したタイミング** で初めて embedding が生成され、提案エンジンの候補対象になります。

### 手順

#### ① プロジェクト内でナレッジを作成

プロジェクト詳細画面の「ナレッジ」タブ → 右上の「ナレッジ作成」ボタン → 必要項目を入力。

#### ② 公開範囲を「全メンバー」に設定

ナレッジ作成画面（または編集画面）の **「公開範囲」** を **「全メンバー」** に変更してから保存してください。

#### ③ 保存時に AI 処理が走る

保存と同時に、Voyage AI による意味理解 (embedding 生成) が裏で実行されます。

ナレッジ・リスク・課題・振り返り・メモなどの **資産入力 (索引化) は、Beginner プランは月 100 件まで無料、Expert / Pro プランは ¥5 / 件** です。これはプロジェクト作成/更新の月 50 回上限とは **別枠** でカウントされます。詳細: [API 利用 ご利用ガイド](./api-usage-guide.md)

> 同じデータを編集・再保存しても、**意味的な変更**（タイトル・本文・タグなど）がなければ AI 処理は走りません。たとえば「公開範囲だけを切り替える」「カテゴリだけ変える」などの操作では追加処理は発生しません。

---

## ステップ 5：別の新規プロジェクトで過去資産が提案される

### 動作確認の流れ

1. ステップ 4 でナレッジ A を「全メンバー」公開する（例：「Excel データ移行で文字化けが発生」）
2. 別の新規プロジェクト B を作成（例：「Excel データを基幹システムに移行」）
3. プロジェクト B の **「参考」タブ** を開く
4. プロジェクト B のタグ・目的・背景・スコープと類似度の高い順に **ナレッジ A が提案候補として並ぶ**
5. 「このプロジェクトに紐付け」をクリックして、プロジェクト B の参考資産として登録

これがたすきばの **「過去案件から知見をつなぐ」中核機能** です。

---

## 重要な設計思想：自プロジェクト内の資産は、そのプロジェクトには提案されない

たすきばの提案エンジンは「**過去の別案件から学ぶ**」ことを目的としています。そのため、次の振る舞いになっています。

| 状況 | 提案に表示されるか |
| --- | --- |
| プロジェクト A で作成したナレッジを、プロジェクト A の「参考」タブで見たい | ❌ **表示されない**（= 自プロジェクトに紐付け済の資産は提案候補から除外） |
| プロジェクト A で作成したナレッジを、別プロジェクト B の「参考」タブで見たい | ✅ 表示される（公開範囲が「全メンバー」の場合） |

> 「同じプロジェクトに既にある資産」を、そのプロジェクトの「参考」として再度提示しても価値が低い、という考え方に基づいた設計です。
> プロジェクト A 内のナレッジを直接参照したい場合は、プロジェクト A の **「ナレッジ」タブ** から一覧できます。

## うまくいかないときの確認ポイント

### 「顧客が選択肢に出てこない」
→ ステップ 1 の顧客データ登録が完了しているかご確認ください。**顧客 0 件のままではプロジェクトを作成できません**。

### 「公開したナレッジが、新規プロジェクトの提案に表示されない」
次の順に確認してください。

1. **公開範囲が「全メンバー」になっていますか？**
   - 「下書き」「自分のみ」のままでは embedding が生成されず、提案エンジンに乗りません。
2. **自分が今見ているプロジェクトに、そのナレッジを紐付けていませんか？**
   - 自プロジェクトに紐付け済の資産は、そのプロジェクトの提案からは除外されます。
3. **プロジェクト作成/更新の月間上限（Beginner プラン）に達していませんか？**
   - **プロジェクト作成/更新 月 50 回** (ADR-0019 改定後) の上限到達後は「縮退モード」となり、プロジェクト関連の AI 処理が一時停止します。
   - **資産入力・チャット検索などの Embedding は、プロジェクト作成/更新の月 50 回上限とは別枠** です (Beginner は月 100 件まで無料)。プロジェクト作成が縮退モードでも、資産入力・チャット検索は枠内で継続利用できます。
   - 月初に自動的にリセットされ、未処理データはまとめて補完されます。
4. **プロジェクト・ナレッジ双方にタグを十分入力していますか？**
   - タグが少ないと類似度スコアが上がりにくく、関連性の弱い候補は表示されないことがあります。

### 「思ったより API 呼び出し回数が増えている」
ナレッジ・課題・振り返りを「公開」に切り替えた瞬間、過去未処理分も含めて embedding 生成が一度に走ることがあります。**「テナント設定 → 使用量」画面** で当月の API 呼び出し履歴を確認できます。

### 「提案エンジンの結果が突然減った／消えた」
**「テナント設定」画面** で「サンプルデータの表示」設定がオフになっていないかご確認ください。サンプルデータをオフにすると、自テナント内の資産のみが提案候補になります（= テナントを開設して間もない時期は候補数が少なくなります）。
