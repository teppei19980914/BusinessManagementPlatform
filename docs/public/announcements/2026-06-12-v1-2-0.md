## アップデートのお知らせ (v1.2.0)

平素より大変お世話になっております。たすきば運営です。

このたび、**たすきば Knowledge Relay v1.2.0** をリリースいたしましたので、主な変更点をご案内いたします。今回は、ご要望の多かった **WBS（タスク）の一括操作の件数制限撤廃・高速化** と **上書きインポートの安定性** の改善に加え、**工数見積もりツール** （RPA/ローコード対応の係数計算・Excel/Word エクスポート）を新たに追加しました。

## 主なアップデート

### 🧮 見積もりに「ツールで見積もる」機能を追加しました

プロジェクトの見積もり画面（PM/TL 向け）に、**係数計算で工数を自動算出する「ツールで見積もる」モード** を追加しました。

#### 2 種類の作成パターン

| ボタン | 用途 |
|---|---|
| **手動で登録** | 確定済み工数を直接入力（従来相当） |
| **ツールで見積もる** | ツール・規模・難易度を選ぶと工数が自動計算 |

#### 係数計算の仕組み

```
見積工数 = 基準時間 (h) × 規模係数 × 難易度係数 × 手法係数
```

開発ツールと区分（要件定義・設計・開発など）の組み合わせに応じた基準時間が自動で設定され、リアルタイムで計算結果が表示されます。

**対応ツール（全 16 種）**: スクラッチ開発 / パッケージ / WinActor / UiPath / Power Automate Desktop / Power Apps / kintone / Pleasanter / OutSystems / Salesforce Lightning / ServiceNow / Mendix / AppSheet / Zoho Creator / その他

すべての値は自由に変更できます。確定前に調整して精度を高めてください。

#### 工数サマリ・エクスポート

画面上部に **サマリパネル** を追加しました。カテゴリ別の小計とバッファ率（デフォルト 20%）を設定でき、**Excel（サマリ + 明細の 2 シート）** または **Word（報告書形式）** でエクスポートできます。

> なお、理論値はシステムの標準プリセットです。実績データが蓄積されるにつれ、組織固有の係数へ精度を高めていけます。テナントごとのカスタムプリセット（案Y）は今後対応予定です。

### 📈 プロジェクトに「分析」タブを新設しました（予定 vs 実績の進捗グラフ）

プロジェクト詳細画面に **分析** タブを追加しました（タブの並びは「ナレッジ一覧」と「参考」の間）。**5 種類のグラフ**で、プロジェクトの進み具合と担当者ごとの工数・負荷を可視化します。

プロジェクトマネージャ／リーダーが、**「完了に向けて今どこまで進んでいるか（現在地）」** と **「どのくらいのペースで消化できているか（生産性）」** を、会議や報告の前にひと目で把握するための機能です。

**① 進捗の遅れ・先行（予実カーブ・折れ線）** — 予定どおりの進み方（予定）と、実際の進み方（実績）を時系列で比べます。

- **グラフの見方**: 横軸は日付、縦軸は WBS のアクティビティ（実作業）の完了割合（0〜100%）です。**実線が「予定」**（予定完了日を迎えたアクティビティの累積割合）、**点線が「実績」**（実際に完了したアクティビティを、その実績完了日で数えた累積割合）です。
- **遅れ／先行がひと目で**: 実線（予定）より点線（実績）が下にあれば「予定より遅れぎみ」、上にあれば「先行」です。線の傾きが急なほど、その時期にたくさん完了している（ペースが速い）ことを表します。
- **本日マーカー**: グラフに本日位置の縦線を引き、上部に「**本日時点 予定◯% / 実績◯%（遅れ◯%）**」と要約を表示します。

**② 消化ペースと効率（担当者別 週次消化工数・積み上げ棒）** — 予実カーブで見えた遅れ／先行の **「なぜ」** を、作業量と効率の面から読み解くためのグラフです。

- 横軸は週、縦軸はその週に完了したタスクの **実績工数（人時）** で、**1 本の棒を担当者ごとに色分け**して積み上げます。タスクには大きいものも小さいものもあるため、**件数ではなく工数で測る**ことで作業量を正しく表します。
- グラフ上部に **工数効率（予定工数 ÷ 実績工数）** を表示します。1 より大きいと見積より効率的、小さいと想定より時間がかかっています。
- 棒が高い週はこなした工数が多く、低い週は少なめです。特定の人の色だけ大きい場合は、その人に作業が集中している（属人化）サインです。担当者が多い場合は **上位 8 人を個別色**、残りは **「その他」**（担当者なしは「未割当」）にまとめます。
- ⚠️ 工数効率は「見積に対する効率」の目安です。難しい仕事は正当に時間がかかるため、**個人の評価・比較には使わず**、チーム全体の傾向把握や見積もり精度の改善にお使いください。

**③ 見積の精度（予実差）（担当者別 予定 vs 実績 工数・グループ棒）** — 担当者ごとに、**PM/PL が記載した予定工数**と**担当者が記載した実績工数**を横並びで比べます。

- 「誰が見積より工数が掛かる／掛からない傾向か」が一目で分かり、**次回の見積もりやタスクの割り振り**の参考になります。棒にカーソルを合わせると、予定・実績とその差（実績 − 予定）が表示されます。
- 予定だけ・実績だけの片側ではなく、**両方が揃ったタスク（完了かつ実工数入力済）** だけを集計するので、公平に比べられます。担当者が多い場合は上位 8 人を個別、残りは「その他」にまとめます。
- ⚠️ こちらも見積もり・割り振りの改善材料としてのご利用を想定しています。個人の評価・比較には使わないことをおすすめします。

**④ 作業量の偏り（担当者別 作業負担・状態別 積み上げ棒）** — **今、誰にどれだけ作業が残っているか**を担当者ごとに比べ、できる人への偏りを防ぐためのグラフです。

- 未完了タスク（未着手・進行中）の予定工数を、担当者ごとに状態別で積み上げます（保留中のタスクは含みません）。棒が高い人ほど今残っている作業が多く、低い人は軽めです。**負荷分散やタスクの割り振り**の検討にお使いください。
- 右上の切替で 2 通りの見方ができます: **「割り振り量」**（割り振られた予定工数そのもの）と、**「個人ペース補正」**（各担当者の過去の実績÷予定比を掛けた予想残工数。得意・不得意やスピードの差を織り込みます）。上部に平均・最も重い人・最も軽い人も表示します。
- ⚠️ 予定工数は見積もりであり、同じタスクでも人によってかかる時間が違います。**正確な負担量や個人の評価ではなく、割り振り検討の材料**としてお使いください。今の残作業が無い人（未完了タスク 0 件）は表示されません。

**⑤ 日別の負荷（8h超）（担当者別 日次工数・ヒートマップ）** — 各担当者の **1 日あたりの予定工数** が上限の 8 時間に達していないか（特定の日への山積み）を、担当者×日付の **表（ヒートマップ）** で一覧します。

- 未完了タスクの予定工数を **1 日ずつに均等に割り振り**、**行＝担当者・列＝日付（本日以降）・マス＝その日の予定工数（時間）** で表示します。マスは **8 時間以内は無色・7 時間超は黄色（警告）・8 時間超は赤色（超過）** に色分けされ、赤や黄色が多い行・列が負荷の集中している担当者・日です。
- ④（残りの**総量**）に対し、⑤は **「いつ 1 日のピークが来るか（山積み）」** を見ます。総量が同じでも、短い期間に詰め込まれていれば 1 日あたりは 8 時間を超えて赤くなります。**予定の前倒し／後ろ倒しや担当の振り直し**で、無理のない計画に整える材料になります。
- ⚠️ 割り振りは予定期間で均等に割った**概算**で、**土日祝も 1 日として割り振ります**（実際の休みを考えると平日 1 日あたりはもう少し増えます）。完了・保留中のタスクは含みません。同じ作業でも人によりかかる時間は違うため、**負荷の偏りに気づくための目安**であり、個人の評価・比較には使わないでください。

**表示するグラフ・対象期間を選べます** — 分析タブの上部にツールバーを用意しました。

- **見たいグラフだけを選んで表示**できます（ボタンで複数選択）。**最初は「WBS 予実カーブ」1 枚だけ**を表示するので、必要なグラフを足していってください（5 枚すべてを並べると見づらいため）。
- **対象期間**（全期間／直近1・3・6ヶ月／カスタムの開始日〜終了日）で絞れます。期間を選ぶと、表示範囲だけでなく**効率・合計・順位などの数値もその期間で計算し直します**。期間は振り返り系（①②③）には過去側、日次工数（⑤）には今後側に適用され、作業負担（④）は「今この瞬間」のため期間の影響を受けません。
- 選んだ表示グラフ・期間は、同じブラウザで開いている間は記憶されます。

**あわせて、WBS（タスク）に「実績工数」欄を追加しました** — アクティビティの実績入力に「実績工数（人時）」を加えました。担当者の方が実績（実績完了日・完了）と一緒に入力すると、上記②③のグラフと工数効率に反映されます。一括実績更新でも対象に含められます。

- **「完了」にするタスクは実績工数が必須になりました**: ステータスを「完了」にする（または進捗率を 100% にする）ときは、**実績工数（人時）を 0 より大きい値で入力**してください（単体・一括とも）。これにより消化工数・工数効率を欠けなく集計できます。一括で完了にする場合は、実績工数を一括指定するか、対象タスクに先に実績工数を入れておいてください。

共通の注意点:

- **表示できる方**: **プロジェクトの PM/PL、またはテナント管理者の方のみ**です（一般メンバーの画面には表示されません）。**完了（クローズ）したプロジェクトでも、振り返りのためにご覧いただけます**。
- **データ源**: グラフは、WBS に入力された「予定完了日」「実績完了日」「完了ステータス」「担当者」「実績工数」から自動で作られます。担当者の方が実績を入力すると、グラフが伸びていきます。

> 今後、分析タブには WBS 以外の観点（課題やリスクの推移など）のグラフも追加していけるよう、共通の土台として設計しています。

### ⚡ WBS（タスク）の一括削除を大幅に高速化しました

タスクをまとめて選んで一度に削除する操作を見直し、**短時間で完了する**ようにしました。

- これまでは、選んだタスクの件数が増えるほど時間がかかり、削除に数十秒お待たせしてしまうことがありました。今回の改善で、**件数が多くてもすばやく完了**します
- タスクが非常に多い場合は、**自動的に小分けにして処理**するため、途中で時間切れになって失敗することが起きにくくなりました
- もし一部の削除が失敗した場合でも、**失敗した分だけを安全にやり直せます**

WBS はタスクが多くなりがちな画面です。整理や作り直しのためにまとめて削除する場面が、これまでよりずっと快適になります。

### 🔧 WBS（タスク）の上書きインポートが大きな WBS でも失敗しないようになりました

エクスポートした CSV を Excel で編集して取り込む「上書きインポート」で、**追加・更新の多い大きな WBS を確定実行すると、途中で時間切れになり「インポートに失敗しました」と表示される**ことがありました。今回、確定実行の内部処理（既存タスクの更新と、作業グループ（WP）の集計の再計算）をまとめて一括で行うよう見直し、**短時間で確実に完了**するようにしました。

- **1 回で取り込める上限は 2,000 行**です。これを超える場合は CSV を分割して取り込んでください
- 万一エラーで取り込みきれなかった場合でも、**同じ CSV をもう一度取り込めば安全に最後まで反映**されます。各行を ID で既存タスクと突き合わせるため、すでに反映済みの行は「変更なし」となり二重には作られません（ID が空の新規行のみ、再取込のたびに作成されます）
- 取り込んだ内容（タスクの値・WP の集計）はこれまでと変わりません

### 🆕 新しい組織の開設（サインアップ）がより簡単になりました

はじめて組織（テナント）を開設するときのサインアップ画面を、迷わず入力できるよう見直しました。

- **組織 ID の入力が不要になりました（自動で割り当て）**: これまで自分で考えて入力する必要があった「組織 ID（ログイン時に使う識別子）」を、**システムが自動で割り当てる**ようにしました（数字の ID。例: 100001）。入力欄そのものを無くし、考える手間をゼロにしました。割り当てられた組織 ID は、サインアップ完了画面と招待メールでお知らせします（※組織 ID は作成後は変更できません）。
- **入力の順番をわかりやすく整理**: 「組織情報 → お名前・メール → プラン選択 →（有料プランのときだけ）請求先情報」の順に並べ替えました。無料の Beginner プランなら請求先の入力は不要で、より少ない入力で開設できます。
- **送信後のメール案内を充実**: 「招待メールを送信しました」の画面で、**届くメールの差出人・件名・到着の目安（通常 1 分以内）・このあとの手順**を先にご案内するようにしました。メール待ちで不安になったり、迷子になったりしにくくなります。

### 🔗 外部データ API 連携インポートを「ベータ」で提供開始しました

これまで CSV ファイルを用意していただいていた他サービスからのデータ移行を、**ファイルなしで直接つないで取り込める**ようにしました（テナント管理者向け・ベータ）。

- 対応サービス: **Notion / Backlog / kintone / Pleasanter / Google スプレッドシート**
- サービスを選んで接続すると、取り込み元（データベース・アプリ・サイト・シート）と項目を読み込み、たすきばの項目に割り当てて取り込めます。取り込める種類（顧客・プロジェクト・WBS・リスク課題・ナレッジ・振り返り）や入力ルール（選択肢・日付の書き方、1 回 5,000 件まで、新規作成のみ）は、これまでの CSV 取り込みと同じです
- **接続に使うトークン／API キーは保存しません**（接続時とプレビュー時に入力し、送信後すぐに破棄します）。閲覧（読み取り）だけできる権限で利用できます
- 設定画面 →「データインポート」→「② 外部データを直接インポートしたい方へ（ベータ）」から開けます

ベータ機能のため、まずは少量で試して、件数や項目が想定どおりかご確認のうえ本番データを取り込んでいただくことをおすすめします。対応サービスの拡充も順次進めてまいります。

### 📢 画面上部のお知らせ帯（周知バナー）を追加しました

メンテナンスや障害など、**全利用者にすぐ気づいてほしい連絡**を、画面の一番上に帯で表示できるようにしました。

- **重要度で色分け**: 高＝赤 / 中＝黄 / 低＝青 で塗り分け、ひと目で重要度が伝わります
- **必要な期間だけ表示**: 「いつからいつまで」を決めて表示し、期間が終わると自動的に消えます
- **「✕」で閉じられます**: 閉じた状態はログイン中のあいだ保たれます。いったんログアウトして再ログインすると、まだ表示期間内であればもう一度表示されます（大切な連絡の見落とし防止）

この帯を作成・配信できるのはたすきば運営のみで、各組織の管理者・メンバーが内容を編集することはありません。個別の通知（ベルのマーク）や「お知らせ」一覧とは別に、全員へ同じ内容を確実にお届けするための仕組みです。

### 🔗 本文に書いた URL が自動でリンクになりました

ナレッジ・リスク・課題・振り返り・プロジェクト概要・メモ・タスク・顧客の備考・コメントなど、各画面の本文欄に `https://…`／`http://…` で始まる URL を書くと、**保存後の表示で自動的にクリックできるリンク**（新しいタブで開きます）になるようにしました。これまでのように URL をコピーし直す手間なく、そのまま開けます。

- **日本語のすぐ前後でも、URL の部分だけを正しくリンクにします**。たとえば「`https://tasukiba.com/login`にアクセスしてください。」のように URL の直後に空白なしで日本語を続けて書いても、`https://tasukiba.com/login` だけがリンクになり、後ろの「にアクセスしてください。」はリンクに含まれません
- 文末の「。」「、」やカッコ（例: 「（詳しくは https://example.com ）」）も、URL に巻き込まずにきれいに分けます
- **特別な書き方は不要**です。これまでどおり URL を貼り付けて保存するだけで大丈夫です

### 📝 タスクに「備考」欄を新設しました

アクティビティ（ACT）に、作業内容（説明）とは別に補足メモを残せる **備考** 欄を追加しました。関連資料の URL や引き継ぎメモなどを書いておけます（任意・最大 1,000 文字）。書いた URL は上記のとおり自動でリンクになり、入力中はプレビューで表示イメージを確認できます。

### 🔒 クローズしたプロジェクトを完全な「読み取り専用」に統一しました

クローズ済みのプロジェクトでは、リスク・課題・ナレッジ・振り返り・WBS（タスク）・ステークホルダーの **追加・編集・削除・コメント投稿ができないように統一** しました。

- これまで一部の画面で、編集ダイアログや削除ボタン、コメントの投稿欄が表示されて操作できてしまう場合があったのを改め、**画面に表示しない**ようにしました
- あわせて、サーバ側でも受け付けないよう **二重で防止** しています
- プロジェクト自体の削除は、これまでどおり行えます

完了した案件の記録を、あとから誤って書き換えてしまう心配がなくなります。

### ✨ その他の改善

- **振り返り一覧の表示を整理**: 振り返り一覧（プロジェクト内・全振り返りの両画面）から、意味が薄くなっていた「下書き／確定」のステータス列を取り除き、見やすくしました（確定の操作は、各行の操作から引き続き行えます）
- **プロジェクト別ナレッジ一覧の「更新者」表示を修正**: プロジェクトの「ナレッジ一覧」タブで、ナレッジを更新しても更新者名が「—」のままになる場合があったのを修正しました（記録は正しく、表示だけの問題でした）
- **WBS 一括編集・一括実績更新の件数上限を撤廃**: 複数タスクをまとめて更新する「一括編集（担当者・優先度・予定日程・予定工数）」と「一括実績更新（ステータス・進捗率・実績日程）」の件数制限を廃止しました。これまで 100 件を超えるとエラーになっていましたが、**大規模プロジェクト（600 件以上）でもそのまま使えるようになりました**。内部で 100 件ずつ自動分割して処理するため、タイムアウトの心配はありません
- **WBS 管理画面の「IDを表示」「工数集計」ボタンを削除しました**: 使用頻度が低く画面を狭くしていた 2 つのボタンを廃止しました。タスク ID の確認は CSV エクスポートから、担当者の日次工数確認は ACT 編集ダイアログ内のプレビューをご利用ください
- **タスクの一括更新も高速化**: 複数のタスクをまとめて更新するとき（担当者・期限・状況などの一括変更）の処理を見直し、対象が多くの作業グループにまたがる場合でも短時間で完了するようにしました。結果はこれまでと変わりません
- **タスクを 1 件ずつ操作するときの応答も軽くしました**: タスクの追加・編集・削除を 1 件ずつ行う際の内部的な無駄な処理を見直しました。表示や記録の内容はこれまでどおりで、操作のレスポンスがほんの少し軽くなります
- **CSV での一括取込を 1 つの入口に整理しました**: 以前あった「ナレッジ・課題のみ」の旧取込ウィザードを廃止し、v1.1.0 で追加した **7 種類（顧客・プロジェクト・WBS・リスク・課題・ナレッジ・振り返り）対応の「① CSVファイルをインポート」に一本化** しました。これまで旧ウィザードをお使いだった方も、新しい画面から同じデータを取り込めます
- **AI ヘルプ「たすきフクロウ」がさらに賢くなりました**: 料金（意味検索や AI 検索用データの単価、ヘルプチャットの無料枠）・公開範囲・提案に出る条件・各画面の入力項目・二段階認証の復旧やログインロックの解除など、これまで答えられなかった／古かった案内を、最新の仕様に合わせて拡充・修正しました。使い方やよくある質問は、画面右下のフクロウにそのままお尋ねください
