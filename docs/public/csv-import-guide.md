# 外部データ CSV 取込手順（テナント管理者向け）

テナント管理者が **初回ログイン後** に、社内 wiki / Excel / 旧プロジェクト管理ツール等で蓄積していた **既存のナレッジ・課題（リスク／イシュー）を CSV ファイルでまとめて取り込む** ための手順書です。エンジニアの方でなくてもお読みいただけるよう、専門用語をできるだけ避けて記載しています。

> **💰 プラン別のインポート時の容量制御**（2026-05-28 仕様、ADR-0020 §11）
>
> ご利用プランによって、CSV インポート時の容量制御が異なります:
>
> | 取込後の予測使用量 | Beginner | Expert / Pro |
> |---|---|---|
> | < 50 MB（無料枠内） | ✅ 取込可 | ✅ 取込可 |
> | 50 MB - 1 GB | **⛔ 取込ブロック** | ✅ 取込可（¥0〜¥50/月の従量課金） |
> | 1 GB - 10 GB | **⛔ 取込ブロック** | ⚠ **警告表示**（取込可、¥50〜¥500/月） |
> | 10 GB - 50 GB | **⛔ 取込ブロック** | ⚠ **警告表示**（取込可、¥500〜¥2,500/月） |
> | ≥ 50 GB（ハードキャップ） | **⛔ 取込ブロック** | **⛔ 取込ブロック**（読取り・エクスポートは可） |
>
> **Beginner プランの方**: 50 MB 無料枠を超える取込は **取込前に自動でブロック** されます（取込画面の preview で警告表示 + 取込ボタンが無効化）。意図せず課金が発生することはありません。50 MB を超えるデータをまとめて取り込みたい場合は **Expert / Pro プランへのアップグレード** をご検討ください。
>
> **Expert / Pro プランの方**: 50 MB 超過分は **¥50/GB tier の従量課金** になります。preview 画面で「取込後の予測使用量」「予測月次課金額」が表示されますので、内容を確認のうえ取込を実行してください。
>
> **共通**: 50 GB は **ハードキャップ**（他テナント保護の技術的安全弁）で、全プランで超過時は取込が拒否されます（既存データは引き続き読取り・エクスポート可能）。
>
> 詳しくは [データ容量 ご利用ガイド](./db-capacity-billing-guide.md) を参照してください。

## 全体の流れ（5 分）

```
[準備] 既存データを CSV (UTF-8) で用意
   ・テンプレート CSV をダウンロードして列構成を確認
   ・Excel で編集 → 「名前を付けて保存」→「CSV UTF-8」
        ↓
[ステップ 1] テナント管理者でログイン → 設定画面を開く
        ↓
[ステップ 2] 外部データ移行ウィザードを開く
   /settings/tenant/external-import
        ↓
[ステップ 3] ファイル選択 + 取込種別を選ぶ（Knowledge / RiskIssue）
        ↓
[ステップ 4] カラムマッピング
   CSV 列名 → サービスのフィールド名 を対応付け
        ↓
[ステップ 5] プレビュー
   件数・エラー行を確認（まだ取込はされない）
        ↓
[ステップ 6] 取込実行
   結果サマリと「取り込んだナレッジを確認」ボタンが表示される
```

## 事前準備：CSV ファイルを用意する

### A. テンプレート CSV をダウンロードする（推奨）

サービスから配布する **テンプレート CSV** を起点に編集すると、列名がそのままサービス側のフィールド名と一致するため、後のマッピング作業を「同名選択」だけで完了でき、エラーが起きにくくなります。

テンプレートのダウンロード手順は本書の [ステップ 2](#ステップ-2外部データ移行ウィザードを開く) で説明します。先にウィザード画面を開いてからダウンロードしても問題ありません。

### B. CSV ファイルのフォーマット要件

| 項目 | 仕様 | 備考 |
| --- | --- | --- |
| 文字コード | **UTF-8** | Excel の既定（Shift_JIS）では文字化けします。Excel から保存する場合は **「CSV UTF-8 (コンマ区切り)」** を選んでください |
| BOM | 付いていても付いていなくても可 | Excel が保存時に自動付与する BOM はサービス側で自動除去します |
| 改行コード | CRLF（`\r\n`）または LF（`\n`）どちらでも可 | RFC 4180 準拠 |
| 1 行目 | **ヘッダ行（列名）** | サービスはこの行を見てマッピング候補を提示します |
| 区切り文字 | **カンマ（`,`）** | タブ区切り（TSV）・セミコロン区切りは非対応 |
| カンマを含むセル | ダブルクォートで囲む（例: `"A, B, C"`） | RFC 4180 標準 |
| 改行を含むセル（textarea 列） | **ダブルクォートで囲む**（例: `"1 行目↵2 行目"`） | 本文・背景・原因など長文を入れる列で重要。詳細は本書 [付録 A](#付録-a-改行を含むセルの書き方重要) を参照 |
| ダブルクォートを含むセル | `"` を `""` に二重化（例: `"彼は ""OK"" と言った"`） | RFC 4180 標準 |
| ファイルサイズ上限 | **50 MB** | 超過すると 413 エラーで弾かれます |
| 1 ファイルあたりの行数上限 | 経路により異なる（後述） | ─ |

### 経路別の行数上限

ご利用になる取込経路によって、1 ファイルあたりの行数上限が異なります。

| 経路 | 行数上限 | 用途 |
| --- | --- | --- |
| **外部データ移行ウィザード**（本書の主経路、`/settings/tenant/external-import`） | **Knowledge + RiskIssue 合計 5,000 行** | 初回大量取込 |
| **エンティティ別 sync-import**（各一覧画面の「インポート」ボタン） | **500 行** | エクスポート → 編集 → 再取込（round-trip 用途） |

500 行を超える sync-import は 413 エラーで弾かれます。大量データを取り込む場合は外部データ移行ウィザード経路をご利用ください。

> **⚠ 改行を含む長文がある場合は必ず付録 A を確認してください**
>
> 2026-05-28 のリリース以前は、本文・背景などに改行を含む CSV を取り込むと **2 行目以降が silent に欠落** する不具合がありました。修正は完了していますが、Excel での編集時にダブルクォート（`"`）が外れる事故は今でも起こり得ます。

## ステップ 1：テナント管理者でログイン → 設定画面を開く

### 対象者
サインアップ済み、または「テナント管理者」ロールを与えられているメンバー。

> **テナント管理者でない方は本機能を利用できません。**
> 「一般ユーザ」「PM/TL」のロールの方は、テナント管理者に取込を依頼してください（取込後のデータは公開範囲に応じて閲覧・編集できます）。

### 手順

#### ① ログインする
組織 ID・メールアドレス・パスワードでログインします。手順は [`account-setup-guide.md`](./account-setup-guide.md) のステップ 2 を参照してください。

#### ② 画面右上のアカウントメニュー →「設定」を開く
ログイン後は通常「プロジェクト一覧」（`/projects`）が表示されます。

ヘッダ右上の **アカウントアイコン → 設定** をクリックすると、`/settings` 画面（個人設定）に遷移します。

#### ③ サイドメニュー（または画面内リンク）から「テナント設定」を開く
`/settings`（個人設定）から **テナント設定 → `/settings/tenant`** に進んでください。

> テナント設定画面は **テナント管理者にのみ表示** されます。表示されない場合は、ご自分のロールが「テナント管理者」になっているかをご確認ください（`/settings` 画面上部の「アカウント情報」セクションでロールが確認できます）。

## ステップ 2：外部データ移行ウィザードを開く

`/settings/tenant`（テナント設定）画面を下にスクロールすると、**「データインポート」セクション** があります。

このセクションには 2 種類の取込機能がありますが、**初回の外部データ取込で使うのは「外部データ移行ウィザード」のほうです**。

| セクション | 用途 | 対象データ |
| --- | --- | --- |
| **データインポート（ZIP 取込）** | サービスからエクスポートした ZIP を別テナントに復元する | 退会前バックアップ・テナント間移行 |
| **外部データ移行ウィザード（CSV）** ← ★こちら | 外部システム（社内 wiki / Excel / 旧 PM ツール）からの **初回データ取込** | Knowledge + RiskIssue |

データインポートセクションの中の **黄色の案内ボックス**「📝 外部システム (Excel / 旧 PM ツール 等) から初回データを取り込みたい方へ」 → **「外部データ移行ウィザード」リンク** をクリックすると、ウィザード画面（`/settings/tenant/external-import`）に遷移します。

> **直接アクセスも可能です**
> ブラウザのアドレス欄に組織のサービス URL に続けて `/settings/tenant/external-import` を入力しても開けます。

ウィザード画面が開くと、上部にステップインジケータ（1. ファイル選択 / 2. マッピング / 3. プレビュー / 4. 結果）が表示されます。

### テンプレート CSV をダウンロードする

ウィザード画面上部に、**テンプレート CSV へのダウンロードリンク** があります。

- 🔗 **Knowledge テンプレート CSV**
- 🔗 **RiskIssue テンプレート CSV**

それぞれをクリックすると、列名と入力例 1 行が入った CSV ファイルがダウンロードされます。Excel で開き、サンプル行を上書きして、ご自身のデータ行を追加していくのが最短経路です。

> **テンプレートを使う最大の利点**
> テンプレートの列名は **サービス側のフィールド名と完全一致** しています。後の「カラムマッピング」ステップで、サービスが **自動的に同名マッピング** を当ててくれるため、手作業のマッピングがほぼ不要になります。

## ステップ 3：ウィザード「Step 1. ファイル選択」

### ① CSV ファイルを選択する
**「CSV ファイル (UTF-8)」** 欄の「ファイルを選択」ボタンを押し、用意した CSV を選びます。

選択直後に、サービスは CSV の **1 行目（ヘッダ行）だけを読み込んで列名を抽出** します。画面下部に「検出列数: N」が表示されれば成功です。

> **失敗時の表示**
> - 「CSV のヘッダ行を検出できませんでした」→ ファイルが空、または 1 行目が読めません。CSV として開いて中身を確認してください
> - 「ファイルを CSV として読み込めませんでした」→ ファイルが壊れている、または UTF-8 でないバイナリです

### ② 取り込むエンティティを選ぶ
**1 つの CSV ファイルから、Knowledge と RiskIssue のいずれか（または両方）を同時に取り込めます**。

- ☑ **Knowledge を取り込む** にチェック → ナレッジとして取り込まれます
- ☑ **RiskIssue を取り込む (リスク + 過去課題)** にチェック → リスクと課題（イシュー）として取り込まれます

> **両方にチェックを入れた場合**
> CSV ファイル 1 つから両エンティティへ振り分け取込できます。マッピング画面で同じ CSV 列を Knowledge 側・RiskIssue 側のどちらにマッピングするかを個別に設定します。通常は **どちらか一方だけ** の利用で十分です。

### ③ RiskIssue の場合: デフォルトプロジェクトを選ぶ
RiskIssue は **必ずどこかのプロジェクトに所属** する必要があります。CSV に `projectId` 列が無い場合は、ここで **「全行を所属させるプロジェクト」** をプルダウンから選択してください。

> **プロジェクトを 1 つも作っていない場合**
> ウィザードを開く前に、まず **プロジェクトを 1 件作成** しておく必要があります。手順は [`project-creation-guide.md`](./project-creation-guide.md) を参照してください。「自社」「社内案件」など任意の顧客・プロジェクト名で構いません（後から RiskIssue を別プロジェクトに付け替えることも可能です）。

### ④「次へ (マッピング設定) →」ボタン
すべて選び終えたら **「次へ (マッピング設定) →」** ボタンを押してください。

## ステップ 4：ウィザード「Step 2. カラムマッピング」

CSV の各列を、サービス側のどのフィールドに紐付けるかを設定します。

### マッピング画面の見方

各 CSV 列名の右側に **プルダウン** があり、サービス側のフィールド名から 1 つ選択します。

- **(取込まない)** を選ぶと、その列のデータは無視されます
- 必須フィールドは **「⚠」マーク** が付きます。1 つでも未マッピングだと次に進めません
- **テンプレート CSV からスタートした場合は、ほぼ全列が自動マッピング済み**（同名一致）になります。確認のみで通常は OK です

### Knowledge のフィールド一覧

| サービス側フィールド | 必須 | 値の制限 / 説明 |
| --- | --- | --- |
| `title`（タイトル） | ✅ | 短い件名 |
| `background`（背景） | ✅ | 経緯・状況。**複数行可** |
| `content`（内容） | ✅ | 本文。**複数行可** |
| `result`（結果） | ✅ | 起きた結果・結論。**複数行可** |
| `knowledgeType`（種別） | 任意 | 値: `failure` / `success` / `lesson` / `template` / `general`（既定: `general`） |
| `conclusion`（結論） | 任意 | 任意の補足 |
| `recommendation`（推奨） | 任意 | 次回への推奨アクション |
| `reusability`（再利用性） | 任意 | 値: `high` / `medium` / `low` |
| `devMethod`（開発方式） | 任意 | 値: `waterfall` / `agile` / `hybrid` |
| `techTags`（技術タグ） | 任意 | **カンマ区切り**（例: `react,nextjs,prisma`） |
| `processTags`（工程タグ） | 任意 | カンマ区切り |
| `businessDomainTags`（業務ドメイン） | 任意 | カンマ区切り |
| `visibility`（公開範囲） | 任意 | 値: `draft`（自分のみ）/ `project`（プロジェクト内）/ `company`（テナント全員）。**既定: `company`** |

> **`visibility` の選び方**
> - `company`: テナント全員に公開（**他プロジェクトの提案エンジン候補に並ぶ** ─ 通常はこれ）
> - `project`: プロジェクト内メンバーのみ
> - `draft`: 自分のみ（**embedding 生成・課金対象外**、提案エンジンには出ない）

### RiskIssue のフィールド一覧

| サービス側フィールド | 必須 | 値の制限 / 説明 |
| --- | --- | --- |
| `type`（種別） | ✅ | 値: `risk`（リスク）/ `issue`（課題） |
| `title`（タイトル） | ✅ | 短い件名 |
| `content`（内容） | ✅ | 本文。**複数行可** |
| `impact`（影響度） | ✅ | 値: `low` / `medium` / `high` |
| `priority`（優先度） | ✅ | 値: `low` / `medium` / `high` |
| `cause`（原因） | 任意 | **複数行可** |
| `likelihood`（発生確率） | 任意 | 値: `low` / `medium` / `high` |
| `responsePolicy`（対応方針） | 任意 | **複数行可** |
| `responseDetail`（対応詳細） | 任意 | **複数行可** |
| `deadline`（期限） | 任意 | **`YYYY-MM-DD` 形式**（例: `2026-12-31`） |
| `state`（状態） | 任意 | 既定値あり（サービスの仕様に従う） |
| `lessonLearned`（教訓） | 任意 | **複数行可** |
| `visibility`（公開範囲） | 任意 | 値: `draft` / `public`。**既定: `draft`** |
| `riskNature`（リスク性質） | 任意（`type=risk` のみ意味あり） | 値: `threat`（脅威）/ `opportunity`（機会） |
| `projectId`（所属プロジェクト ID） | 条件付き必須 | 列マッピング無しの場合は Step 1 のデフォルトプロジェクトに所属。**列をマッピングした場合は、CSV 値が有効なプロジェクト ID** である必要あり |

> **`projectId` の入手方法**
> プロジェクトを作成すると、URL の末尾に表示される（例: `/projects/abc123-...`）。CSV にプロジェクト ID 列を持たせる代わりに、ステップ 3 の「デフォルトプロジェクト」で 1 つに集約するのが簡単です。

### ④「プレビューを表示 →」ボタン
マッピング設定が終わったら **「プレビューを表示 →」** ボタンを押してください。

> **このタイミングで起こり得るエラー**
> - 「`<エンティティ名>` の `<フィールド名>` が未マッピングです」→ 必須フィールドが未マッピング。プルダウンから選び直してください
> - 「RiskIssue の `projectId` 列マッピングがない場合、デフォルトプロジェクトを選択してください」→ Step 1 に戻って「全行を所属させるプロジェクト」を選択
> - 「プレビューに失敗しました」→ 後述の [トラブルシューティング](#トラブルシューティングよくあるエラーと対処) を参照

## ステップ 5：ウィザード「Step 3. プレビュー（取込前確認）」

プレビュー画面では、**まだ取込は実行されていません**。次の情報が表示されます。

### 表示内容

1. **Knowledge / RiskIssue ごとの件数**
   - 「合計 N 行」
   - 「取込可能 N 行」（緑表示）
   - 「エラー N 行」（赤表示、ある場合のみ）

2. **CSV インポートは無料**（緑のバナー）
   - embedding 生成の回数を表示しますが、料金は **¥0**（ADR-0019 / 2026-05-24 から全プラン無料化済み）

3. **エラー詳細一覧**（エラー行がある場合）
   - 行番号・対象エンティティ・問題のあるフィールド・理由を一覧表示
   - 最大 50 件まで表示。残りは取込実行後に修正して再アップロードする想定

### ⚠ ここでよく確認すること

- **取込可能件数が想定通りか**
- **エラー行が許容範囲か**（多数のエラーがあれば、CSV を修正してから再度プレビュー）
- **値の制限を守れているか**（`impact=High` ではなく `impact=high`、`deadline=2026/12/31` ではなく `deadline=2026-12-31` など、半角小文字・ハイフン区切りであることに注意）

### ⑥「📥 取込実行」ボタン

エラー行が許容範囲なら **「📥 取込実行」** ボタンを押します。確認ダイアログで「OK」を押すと実際の取込が始まります。

> **取込中の振る舞い**
> - 件数によっては数十秒〜数分かかります（embedding 生成のため）
> - 画面を閉じずにお待ちください
> - **エラー行は取込されずスキップ** され、正常行のみが作成されます
> - 取込されたデータはすべて **新規作成** されます（既存データの上書きは行いません）

## トラブルシューティング：よくあるエラーと対処

### 1. 「ファイルを CSV として読み込めませんでした」「CSV のヘッダ行を検出できませんでした」

**原因**: ファイルが UTF-8 でない（Shift_JIS など）、または壊れている

**対処**: Excel で開き直し、「名前を付けて保存」→ ファイルの種類 **「CSV UTF-8 (コンマ区切り)」** を選んで再保存してください

### 2. 「ファイルが空です」「アップロードサイズが上限 (50 MB) を超えています」

**原因**: ファイルサイズが 0 / 50 MB 超

**対処**: 1 ファイルを 1,000 〜 5,000 行程度に分割して取込を分けてください

### 3. プレビュー画面で「エラー N 行」が表示される

代表的なエラー原因と対処:

| エラー内容例 | 原因 | 対処 |
| --- | --- | --- |
| `title が空です` / `content が空です` / `background が空です` 等 | 必須フィールドが空 | Excel で該当行の値を入力 |
| `knowledgeType は failure/success/lesson/template/general のいずれか` | 値の制限違反（既定の語彙以外） | 表のいずれかに修正 |
| `impact は low/medium/high のいずれか` | 大文字小文字・全角の違い | **半角小文字** に統一 |
| `deadline が YYYY-MM-DD 形式ではありません` | `2026/12/31` 等のスラッシュ区切り | `2026-12-31` のハイフン区切りに修正 |
| `projectId が見つかりません` | 存在しないプロジェクト ID を指定 | Step 1 でデフォルトプロジェクトに集約するか、CSV 値を修正 |

### 4. 取込後にナレッジ本文の「2 行目以降」が消えている

**原因**: 改行を含むセルがダブルクォートで囲まれていなかった（または Excel で保存時にクォートが外れた）

**対処**: 本書 [付録 A](#付録-a-改行を含むセルの書き方重要) を参照のうえ、CSV を直接テキストエディタ（メモ帳・VS Code 等）で開いて、長文セルが `"..."` で囲まれているか確認してください。問題があれば修正して再取込（重複が増えるため、必要であれば取込済みデータを削除してから）。

### 5. プレビュー画面に到達できない／500 エラー

**原因**: CSV 形式の根本的な異常（閉じられていないクォート、ヘッダ行とデータ行の整合性なし、など）

**対処**:
- CSV を直接テキストエディタで開き、ダブルクォートが全て対になっているか確認
- ヘッダ行の列数とデータ行の列数を確認（足りない列は空欄で揃える）
- 上記でも解決しない場合は、本書末尾の [お問い合わせ](#お問い合わせ) からご相談ください

### 6. 取込実行ボタンが押せない

**原因**: 取込可能件数が 0、または警告がある

**対処**:
- プレビュー画面のエラー行を解消してから、戻る → ファイル選択し直し → 再プレビュー
- Beginner プラン上限などの警告がある場合は、プラン・席数を確認

## 付録 A：改行を含むセルの書き方（重要）

**本文・背景・原因・対応方針・対応詳細・教訓・結果** など、複数行になり得るフィールドを CSV に含める場合、**そのセル全体を必ずダブルクォート（`"`）で囲んでください**。

### 正しい例（CSV を直接編集する場合）

```csv
title,background,content,result
"テスト DB 消失","リリース前検証中、
複数チームが共有する DB を
意図せず truncate した","原因はマイグレーションスクリプトの
WHERE 句不足で、影響範囲を
限定する条件が漏れていた","チーム全体の作業が 1 日停止、
以降は dry-run + CI 必須化"
```

### Excel で編集する場合のコツ

1. **セル内改行**: `Alt + Enter`（Windows）/ `Option + Command + Enter`（macOS）でセル内に改行を入れる
2. **保存形式**: 「CSV UTF-8 (コンマ区切り)」を選ぶ
3. **保存後の確認**: 念のため、保存後に CSV ファイルを **メモ帳や VS Code** で開いて、改行を含むセルがちゃんと `"..."` で囲まれているか目視確認すると安心です

### よくある誤り

| 誤った書き方 | 結果 |
| --- | --- |
| `テスト,本文に,カンマがある` | カンマで列が分割されてしまう（→ `"テスト,本文に,カンマがある"` と囲む） |
| `本文に "引用符" がある` | 引用符がエスケープされず壊れる（→ `"本文に ""引用符"" がある"`） |
| 改行を含むセルをクォートで囲まずに保存 | **2 行目以降が別レコードと解釈されて取込結果が壊れる** |

## 補足: 振り返り／メモ／WBS の取込について

本ウィザードでは **Knowledge と RiskIssue のみ** を取り込めます。それ以外のデータ種別は、以下の **個別の取込経路** を使用してください（いずれも対象のエンティティを **エクスポート → 編集 → 再インポート** する「上書きインポート（同期）」型で、初回大量取込の用途には不向きです）。

| データ種別 | 取込経路 | 備考 |
| --- | --- | --- |
| **振り返り（Retrospective）** | プロジェクト画面 → 振り返り → 「インポート」ボタン | プロジェクトに紐付くため、プロジェクトを先に作成 |
| **メモ（Memo）** | 画面上部メニュー →「メモ」→ 「インポート」ボタン | ユーザ単位（プロジェクトに紐付かない） |
| **WBS（タスク）** | プロジェクト画面 → タスク → 「インポート」ボタン | プロジェクトに紐付くため、プロジェクトを先に作成 |

上記経路はいずれも **ID 列を持つ CSV**（サービスからエクスポートした CSV）を上書き取込する仕組みです。外部システムからの初回投入には、まずスプレッドシートで「ID 列だけ空欄」の CSV を作って取り込むことで新規作成として扱われますが、列順や必須フィールドの仕様が個別に異なるため、本ウィザードのような自動カラムマッピングはできません。詳細な手順が必要な場合は、本書末尾の [お問い合わせ](#お問い合わせ) からご相談ください。
