# 提案エンジン v2 改修効果の検証記録

PR-X5 / PR-X6 で実施した提案エンジン改修の効果を **before / after で定量記録** する。

ユーザの「**0 件にしない**」要件と、シードデータ拡充 + 件数保証ロジックによる構造的改善を、
スクショと数値で可視化することで、サービスとしての信頼性を担保する。

## 1. 検証目的

- シードデータ拡充 (PR-X5) と段階表示 UI + 件数保証 (PR-X6) の **複合効果** を可視化する
- 「請求書発行システム構築」のような実プロジェクトで提案 0 件 → 多数件への改善を実測する
- API 応答時間 / クエリ実行回数 / Voyage コスト等の **運用パフォーマンス指標** を継続観測する

### 3-3. 失敗の構造的原因 (改修前)

1. シードナレッジのタグが英語スネーク (`finance` / `invoicing`) で、ユーザの日本語タグと交差ゼロ
2. embedding が NULL のため意味類似度 (重み 50%) がゼロ化
3. pg_trgm のスコア (0.0318) × 重み 0.2 = 0.00636 が `SUGGESTION_SCORE_THRESHOLD = 0.05` を下回る
4. → すべての候補が足切りされ提案 0 件

詳細は [V1_FINAL_TASKS.md PR-X5/X6](../roadmap/V1_FINAL_TASKS.md) を参照。

## 4. 中間検証 (PR-X5 完了時) — 2026-05-07

### 4-1. 投入結果

PR-X5 マージ後、本番に対して以下を実施 (DB target: `aws-1-ap-northeast-1.pooler.supabase.com:5432`):

```bash
# 1. 旧シード 30 件 (knowledgeType='lesson_learned'/'pattern') を論理削除
UPDATE knowledges SET deleted_at = NOW() WHERE ...;  -- 30 行更新

# 2. 事前生成 embedding を生成 (Voyage API)
pnpm seed:generate-embeddings  # 115 件全件成功

# 3. 本番 seed 投入
pnpm db:seed:suggestion
# → knowledges: 30 件投入 + 20 件スキップ + 30 件 embedding 付き
# → サンプルプロジェクト: 10 件冪等スキップ (前回投入済)
# → サンプル課題: 40 件冪等スキップ
# → サンプル振り返り: 15 件冪等スキップ

# 4. ユーザ手動分への backfill
pnpm seed:generate-embeddings --backfill-existing
# → knowledges 32 件 / risks_issues 45 件 / retrospectives 3 件 / projects 4 件
# → 計 84 件 backfill 成功
```

### 4-5. 残課題 (PR-X6 で対応)

PR-X5 で「0 件問題」は **「請求書発行システム構築」(= PowerPlatform / 経理) プロジェクトでは解消** されたが、以下のリスクが構造的に残る:

| 課題 | 現状 | PR-X6 での対応 |
|---|---|---|
| 閾値 `SUGGESTION_SCORE_THRESHOLD = 0.05` で足切り | サンプルと完全に異なる業務領域 (例: 養蜂、葬儀、林業) では候補ゼロのリスク | 閾値を 0.01 に緩和 + **最低件数保証ロジック** で構造的に 0 件を排除 |
| 全候補がフラットに並ぶ | 「強く関連」「弱く関連」の区別が UI 上ない | 段階表示 (strong / medium / weak) で視覚的に整理。2026-05-29 改修で「強く関連 上位 5 件 + 6 件目以降アコーディオン」「中程度の関連 (旧: 関連の可能性) デフォルト折りたたみ」「弱い関連性 デフォルト折りたたみ」へ進化 (詳細: [docs/specification/SUGGESTION_FEATURE.md §3.6](../specification/SUGGESTION_FEATURE.md)) |
| 上位 10 件で足切り | スコア 30% 未満の候補が見えない | `SUGGESTION_DEFAULT_LIMIT` を 50 に緩和 |
