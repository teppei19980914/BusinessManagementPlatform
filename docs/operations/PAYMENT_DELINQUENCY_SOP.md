# 支払い滞納 対応 SOP (Payment Delinquency Standard Operating Procedure)

本文書は、請求書 / 銀行振込払いの顧客が支払いを遅延・滞納した場合の **super_admin の手順書** である。対外的なルール定義は [../business/PAYMENT_TERMS.md](../business/PAYMENT_TERMS.md) を参照。

## 想定読者と前提

- **読者**: super_admin (本サービスの運営担当 1〜2 名)
- **想定スケール**: 顧客テナント数 数件〜10 件未満、滞納件数 月 1〜2 件程度
- **自動化の有無**: 自動催促・自動 read-only 化は **未実装**。本 SOP は手運用前提
- **必要権限**: super_admin (`/admin/super` 配下の全機能アクセス可)、Supabase SQL Editor 直接アクセス、メールアカウント (請求書送信元)

---

## §0. 月次入金確認 (定常作業) — 2026-05-14 改訂

請求サイクル: **月末締め + 翌月15日請求書発行 + 翌月25日支払**
([PAYMENT_TERMS.md §1.1](../business/PAYMENT_TERMS.md#11-請求サイクル-2026-05-14-確定-月末締め--翌月15日請求書発行--翌月25日支払))

### 実施タイミング

| 期間 | 作業内容 | 頻度 |
|---|---|---|
| 翌月 16〜25日 | 銀行口座での入金確認・消込 | 隔日〜毎日 |
| **翌月 26日朝** | 前日 (25日) 支払期限到来後の未入金リスト確認 → 滞納フロー開始 | **月 1 回必須** |

**例: 5月利用分の場合**
- 6/16〜6/25: 入金消込期間
- 6/26 朝: 未入金検知 → 滞納テナントは §1 へ

### 手順

1. **銀行口座を確認**:
   - 銀行口座 (法人ネットバンキング) → 振込履歴を当月分チェック
   - Stripe Dashboard (現状未連携。連携完了後に追記)
2. **テナント別の入金消込**:
   - 別途運用シート (Google Sheets 等) で「請求書 No. / 顧客 / 期日 / 金額 / 入金日」を管理
   - 入金確認できた請求書に「✅ 消込済」を記録
3. **滞納候補の抽出 (毎月26日朝に必須実施)**:
   - 支払期限 (前月分なら当月25日) を過ぎているのに入金確認できていないものを特定 → §1 へ
   - フェーズ判定の経過日数は **「支払期限 (= 翌月25日) からの経過日数」** で計算する

> Stripe Metered Billing 連携 ([../business/TENANT_AND_BILLING.md §34.14.8](../business/TENANT_AND_BILLING.md)) が完了後は、Stripe Webhook の `invoice.payment_failed` で自動検知に切替予定。本 SOP §0 はそれまでの暫定運用。

## §1. 滞納検知時の初動

### 1.1 滞納情報の整理

滞納候補を発見したら、以下の情報を整理する (運用シート / Notion 等にメモ):

```
- テナント slug:
- テナント名 (Tenant.name):
- 請求書 No.:
- 請求金額:
- 請求書発行日:
- 支払い期日:
- 経過日数 (期日からの日数):
- billingContactEmail:
- billingPhoneNumber (あれば):
- billingContactName:
- 過去の滞納履歴 (前回いつ何日遅延したか):
```

### 1.2 経過日数からフェーズを判定

**経過日数の起算日 = 支払期限 (= 締日翌月25日、固定)**。

| 経過日数 | フェーズ | 進む先 | 例 (5月利用分、支払期限 6/25) |
|---|---|---|---|
| 1〜30 日 | フェーズ 1: 軽度遅延 | §2 へ | 6/26〜7/25 |
| 31〜60 日 | フェーズ 2: 重度遅延 | §3 へ | 7/26〜8/24 |
| (任意フェーズで連絡途絶 14 日) | フェーズ 3: 連絡不通 | §4 へ | 連絡途絶開始から 14 日後 |
| 61 日以上 / 倒産情報あり | フェーズ 4: 回収不能 | §5 へ | 8/25 以降 |

判定の根拠ルールは [PAYMENT_TERMS.md §2.1](../business/PAYMENT_TERMS.md#21-全体像) を参照。

## §2. フェーズ 1: 軽度遅延 (期日 +1〜+30 日)

### 2.1 対応方針

**利用制限なし**。リマインダーメールのみで穏便に対応する。

### 2.2 リマインダー送信タイミング

| 経過日数 | 送信内容 |
|---|---|
| +3 日 | リマインダー 1 通目 (穏便) |
| +14 日 | リマインダー 2 通目 (要確認の度合いを上げる) |

## §3. フェーズ 2: 重度遅延 (期日 +31〜+60 日)

### 3.1 対応方針

**read-only モード移行**。新規 API 課金を止めて回収難度を上げない。

### 3.2 移行前予告 (移行 2 営業日前)

#### テンプレ
```
件名: 【重要】サービス利用制限のお知らせ (請求書 No. {{invoice_no}})

{{billingContactName}} 様

たすきば Knowledge Relay 運営の {{super_admin_name}} です。

請求書 No. {{invoice_no}} (お支払い期日 {{due_date}}) について、複数回のご案内にもかかわらず
お支払いの確認ができておりません。

つきましては、利用規約 第 X 条に基づき、{{suspension_date}} (本メール送信の 2 営業日後) より
貴テナントを **閲覧専用 (read-only) モード** へ移行させていただきます。

【read-only モードでの動作】
- ログイン: 可能
- 既存データの閲覧: 可能
- データのエクスポート: 可能
- 新規プロジェクト作成 / リスク起票 / コメント投稿等の書き込み: 不可
- 提案エンジンの新規生成: 不可

お支払いを確認次第、即座に解除いたします (即時反映)。

何か事情がございましたら、{{suspension_date}} までにご返信ください。
分割払い等のご相談にも応じております。

---
たすきば Knowledge Relay 運営
{{super_admin_email}}
```

### 3.3 read-only 移行操作 (技術手順)

> **重要**: 専用フラグ (`Tenant.suspendedAt`) は v1.x で追加予定。**v1 (2026-06-01 リリース) 時点では以下の暫定手順** で対応。

#### 暫定手順 (v1 期間限定)

1. Supabase SQL Editor で対象テナントを特定:
   ```sql
   SELECT id, slug, name, plan, beginner_ever_upgraded
   FROM tenants
   WHERE slug = '<tenant-slug>'
     AND deleted_at IS NULL;
   ```
2. 現プランをメモ (解除時に戻す):
   ```
   テナント: <slug>
   元プラン: <plan>          -- 例: 'expert' または 'pro'
   beginnerEverUpgraded: <true/false>
   ```
3. **Beginner プランへの強制降格 + 月間上限超過状態の擬似再現** で read-only 化:
   ```sql
   -- ⚠️ 解除時に必ず元に戻すこと
   UPDATE tenants
   SET plan = 'beginner',
       current_month_api_call_count = 9999999,  -- 上限超過状態にして縮退
       updated_at = NOW()
   WHERE slug = '<tenant-slug>';
   ```

   > **限界**: この方式では「書き込み禁止」までは強制できず、提案エンジンの縮退モードに留まる。完全な書き込み禁止は v1.x の `suspendedAt` 実装を待つ。
   > 暫定的に厳格な制限が必要な場合は、後続手順 4 で `deletedAt` セット (= ログイン不可) も検討。

4. **より厳しい措置 (ログイン不可)** を取る場合は、`deletedAt` を一時セット:
   ```sql
   -- ⚠️ ログイン不可。エクスポートも顧客自身では取れなくなる。
   -- 顧客から事前に「データ引き上げ用エクスポート要請」が来た場合のみ実施。
   UPDATE tenants SET deleted_at = NOW() WHERE slug = '<tenant-slug>';
   ```
   この場合は purge 対象になる前 (P-F: 削除後 90 日後物理削除) に解除すること。

5. 移行通知メールを送信:
   ```
   件名: 【ご連絡】サービス利用制限を実施しました (請求書 No. {{invoice_no}})

   {{billingContactName}} 様

   {{date}} より、貴テナントを閲覧専用モードに移行しました。
   お支払い完了次第、即座に解除いたします。
   {{super_admin_email}}
   ```

### 3.4 並行アクション (期日 +31 日 / +45 日)

- **電話**: `billingPhoneNumber` があれば営業時間内に発信。応答なしの場合は留守電 (録音内容も後の証拠になる)
- **担当営業 / 紹介者経由の連絡**: 顧客との接点を持つ社内担当者経由で接触を試みる
- **コミュニケーションログ**: 電話日時 / 内容を運用シートに記録

### 3.5 解除手順 (入金確認後)

1. 入金確認 (銀行口座 / Stripe で日付・金額を一致確認)
2. 元のプランに戻す:
   ```sql
   UPDATE tenants
   SET plan = '<元プラン>',                 -- 'expert' or 'pro'
       current_month_api_call_count = <移行前の値 or 0>,  -- 値が分からなければ 0 にして月初リセット待ち
       updated_at = NOW()
   WHERE slug = '<tenant-slug>';
   ```
3. (deletedAt セットしていた場合) 解除:
   ```sql
   UPDATE tenants SET deleted_at = NULL WHERE slug = '<tenant-slug>';
   ```
4. 解除通知メール送信:
   ```
   件名: 【ご連絡】サービス利用再開のご案内

   {{billingContactName}} 様

   お支払いを確認いたしましたので、貴テナントの利用制限を解除いたしました。
   引き続きご活用いただけますと幸いです。
   {{super_admin_email}}
   ```
5. 運用シートに「解除日 / 入金日 / 入金額」を記録

## §4. フェーズ 3: 連絡不通

### 4.1 連絡不通の判定

[PAYMENT_TERMS.md §2.4](../business/PAYMENT_TERMS.md#24-フェーズ-3-連絡不通-任意フェーズで-14-日連絡途絶) の 3 条件すべてに該当した時点で本フェーズへ。

### 4.2 内容証明郵便の送付

#### 送付判断
- 債権額 ¥10,000 以上: 送付推奨
- 債権額 ¥10,000 未満: 送付スキップ可 (営業判断)

#### 法人住所の特定
- 国税庁 法人番号公表サイト (https://www.houjin-bangou.nta.go.jp/) で正式な登記住所を確認
- `Tenant.billingAddress` (旧フィールド) または `billingPostalCode` + `billingPrefecture` + `billingCity` + `billingStreetAddress` (新構造化フィールド) と照合
- **登記住所と請求住所が異なる場合は登記住所優先** (法的有効性のため)

#### 内容証明テンプレ

```
                                    通知書

                            令和  年  月  日
                            (差出人: 弊社住所・社名・代表者名)

(宛先: 顧客の登記住所・法人名・代表者名)

冠省 当社は、貴社との間で締結した「たすきば Knowledge Relay」サービス利用契約
(契約日: {{contract_date}}、契約 ID: {{tenant_slug}}) に基づき、貴社に対し
下記のとおりサービス利用料の請求権 (以下「本債権」) を有しております。

         記

1. 債権額: 金 {{amount}} 円
2. 内訳: {{period_from}} 〜 {{period_to}} 期分のサービス利用料
3. 請求書番号: No. {{invoice_no}}
4. 支払期日: 令和  年  月  日

しかし、貴社からは支払期日を経過して  日が経過した本書面到達日現在に至るも、
本債権の弁済を受けておりません。

つきましては、本書面到達後 14 日以内に上記金額を下記口座へお振込みいただきますよう
請求いたします。

万一、上記期間内に弁済がない場合は、誠に遺憾ながら法的手段を採らせていただく
所存であることを念のため申し添えます。
                                                               草々

(振込先口座)
{{bank_account_info}}
```

#### 送付手順

1. 郵便局窓口で **内容証明郵便 + 配達証明** をオプション指定して提出 (郵送費 約 1,250 円)
2. 控え (証明印付き原本コピー) を `docs/operations/legal-archive/YYYY/<tenant-slug>/naiyo-shomei.pdf` で保管 (5 年間)
3. 配達証明はがきが返送されたら同フォルダに保管

### 4.3 法務確認

- 顧問弁護士 (未契約なら商工会議所の無料法律相談 / 法テラス) に手順を確認
- 訴訟に進む場合の費用対効果を試算 (60 万円以下は少額訴訟が選択肢)

### 4.4 続報待ち期間中の状態

- read-only モードを維持 (フェーズ 2 の手順で適用済の状態を継続)
- データは凍結保存 (削除しない)
- 顧客からの連絡再開があれば、まずフェーズ 2 の解除条件 (= 入金) を再提示し、状況に応じて分割払い等を相談

## §5. フェーズ 4: 回収不能

### 5.1 回収不能の認定条件

[PAYMENT_TERMS.md §2.5](../business/PAYMENT_TERMS.md#25-フェーズ-4-回収不能-倒産--期日-90-日以上) のいずれかに該当。

### 5.2 倒産・破産の場合

#### 情報源
- **官報**: https://kanpou.npb.go.jp/ (破産手続開始公告は無料で確認可)
- **帝国データバンク / 東京商工リサーチ**: 大口取引先のみ有料調査依頼
- **本人通知**: 顧客から「破産します / 廃業します」の連絡を受けた場合

#### 債権届出の手順 (債権額 ¥50,000 以上のみ推奨)

1. 官報で破産事件番号 / 破産管財人を確認
2. 破産管財人 (弁護士事務所) に電話して債権届出書のフォーマットを取得
3. 債権額・発生原因・証拠書類 (請求書 PDF コピー) を添付して提出
4. 配当があれば後日入金される (大半は配当 0%)

#### データ削除手順

1. **CSV エクスポート取得** (削除前の最終確認):
   ```sql
   -- super_admin が /admin/super/tenants/<id>/export で取得
   -- または手動で全テーブルを CSV ダンプ
   ```
2. エクスポート CSV を `docs/operations/legal-archive/YYYY/<tenant-slug>/final-export/` に **5 年間保管**
3. 30 日待機 (倒産通知から 30 日後に削除実施)
4. テナント削除:
   ```
   /admin/super/tenants/<id> → 「テナントを削除」操作
   (内部的に soft delete → 90 日後に purgeOldDeletedTenants で物理削除)
   ```
5. 運用シートに削除完了日を記録

### 5.3 期日 +90 日超 + 連絡不通の場合

#### 削除予告メール (削除 14 日前)

```
件名: 【最終通知】サービス契約解除およびデータ削除のご案内

{{billingContactName}} 様

たすきば Knowledge Relay 運営です。

請求書 No. {{invoice_no}} について、お支払い期日から 90 日以上が経過し、
複数回のご連絡にもご返信いただけない状況です。

つきましては、利用規約 第 X 条に基づき、本メール送信日から 14 日後の
{{deletion_date}} をもって、貴テナントの契約を解除し、データを削除いたします。

データの引き上げをご希望の場合、{{deletion_date}} までにご連絡ください。

引き続きご利用をご希望の場合は、未払金 {{amount}} 円のお振込みをもって
本通知を撤回いたします。

---
たすきば Knowledge Relay 運営
{{super_admin_email}}
```

#### 削除実施

1. 14 日経過しても連絡なし / 入金なしを確認
2. CSV エクスポート取得 → `docs/operations/legal-archive/YYYY/<tenant-slug>/final-export/` に保管
3. テナント削除 (上記 §5.2 と同手順)
4. 債権放棄処理:
   - 経理担当に「○○年○月期 売掛金 ¥{{amount}} を回収不能として損金処理」と申請
   - 損金算入の根拠資料 (内容証明控え / 配達証明 / 削除予告メール送信ログ) を `docs/operations/legal-archive/YYYY/<tenant-slug>/debt-forgiveness/` に保管 (5 年間)

## §6. エスカレーション基準

以下の場合は **super_admin 単独判断ではなく** 経営層 / 顧問弁護士に相談する:

| 事象 | エスカレーション先 |
|---|---|
| 債権額 ¥100,000 超 で滞納発生 | 経営層 (即時報告) |
| 顧客が法的措置を示唆 (弁護士からの通知書受領) | 顧問弁護士 (即時) |
| 報道済みの倒産案件 | 経営層 (経理・法務同席で対応会議) |
| 個人情報保護法・データ削除要請とのコンフリクト | 顧問弁護士 + DPO 相当者 |
| read-only 化に対する顧客側の強い反発 (SNS 拡散等のリスク) | 経営層 + 広報担当 |

## §7. 月次レポート (報告義務)

super_admin は **毎月初** に経営層へ以下のレポートを提出する:

- 当月の滞納件数 (フェーズ別)
- 当月の解決件数 (入金完了 / 削除完了)
- 当月の累計未回収額
- 内容証明送付件数
- 削除実施件数
- 翌月の対応予定 (フェーズ 4 進入予定の案件 等)

レポートテンプレ:
```
# {{YYYY-MM}} 滞納状況レポート

## サマリ
- 滞納中テナント数: N 件
  - フェーズ 1 (軽度): X 件
  - フェーズ 2 (重度): Y 件
  - フェーズ 3 (連絡不通): Z 件
  - フェーズ 4 (回収不能進行中): W 件
- 累計未回収額: ¥XXX
- 当月新規滞納: M 件
- 当月解決: K 件 (入金 K1 / 削除 K2)

## 個別案件
| テナント | フェーズ | 経過日数 | 金額 | 次のアクション |
|---|---|---|---|---|
| ... | ... | ... | ... | ... |

## 翌月予定
- ...
```

## §8. SOP の改善サイクル

- **6 ヶ月に 1 回** SOP の見直しを実施 (滞納事例が発生した実績ベースで手順を補正)
- 大きな事例 (フェーズ 4 まで進んだ案件) が出た場合は、終了直後に **振り返り** を行い、本 SOP に教訓を追記
- 自動化 (Stripe Webhook / `Tenant.suspendedAt` フラグ) が実装されたら、該当セクションを置換
