# ADR-0013: Beginner プランへのダウングレード禁止 (悪用防止ルール)

- **Status**: Accepted (Beginner 上限値は [ADR-0019](./0019-billable-feature-units-and-free-tier-expansion.md) で 100 → 50 に改定、2026-05-24)
- **Date**: 2026-05 (TENANT_AND_BILLING 確定版で正式採用)
- **Deciders**: teppei

> 🆕 **ADR-0019 (2026-05-24)**: Beginner プランの月次上限が 100 → 50 (課金対象 call のみカウント) に改定。本 ADR のダウングレード禁止ルールは継続有効。詳細: [ADR-0019](./0019-billable-feature-units-and-free-tier-expansion.md)。

---

## Context

[ADR-0002](./0002-tenant-billing-per-api-call.md) の per-API-call 従量課金モデルにおいて、テナントがプランを切り替える際のルールを決める必要があった。
Beginner / Expert / Pro の 3 プランがあり、それぞれ単価と無料枠が異なる:

| プラン | 月額固定 | 月内無料枠 | 上限超過時 |
|---|---|---|---|
| Beginner | ¥0 | 100 回 | 縮退モード ([ADR-0008](./0008-graceful-degradation-mode.md)) |
| Expert | ¥0 | — | ¥5 / 回 (Haiku) |
| Pro | ¥0 | — | ¥15 / 回 (Sonnet) |

検討時の論点:

- **「Expert で使い倒して月末に Beginner に戻す」悪用シナリオ**: 当月分の課金を Expert 単価で確定させてしまえば、月末に Beginner にダウングレードしても課金額は変わらない…と思いきや、翌月から無料枠 100 回を再び使えるようになる。これが繰り返されると、実質「Expert の課金から逃げる」抜け道になる
- **「Beginner で使い切ったあと急に Expert にアップグレード」は OK**: これは正常な収益化フローなので即時許可したい
- **「Pro 高すぎたから Expert に戻す」もユースケースとしては正当**: per-call 単価が違うだけなので、月途中切替は単価で吸収できる

### 悪用シナリオの具体例

```
Month 1 (Beginner): 100 回無料で使用
Month 1 月末: Expert にアップグレード、追加 50 回使用 (¥250)
Month 1 月末: Beginner にダウングレード予約
Month 2 (Beginner): また 100 回無料で使用
Month 2 月末: 同じく Expert + ダウングレードを繰り返す
```

このパターンを許すと、本来 Expert プランで継続課金してもらうべきヘビーユーザが、毎月「無料枠 100 回 + Expert で必要分だけ追加」を繰り返せてしまう。**Expert プランのビジネス価値が毀損する**。

## Decision

**Beginner プランへのダウングレードは禁止する** (Beginner → Expert / Pro へのアップグレードのみ許可)。

### プラン切替ルールマトリクス

| from \ to | Beginner | Expert | Pro |
|---|---|---|---|
| Beginner | — | ✅ 即時 | ✅ 即時 |
| Expert | ❌ **禁止** | — | ✅ 即時 |
| Pro | ❌ **禁止** | ✅ 即時 | — |

### UI 仕様

- テナント設定の課金プラン画面で、Beginner プランの選択肢を **disabled** にする (Expert / Pro テナントの場合)
- 「Beginner にダウングレードしたい場合は、テナントの一時停止 / 解約を検討してください」と注釈
- どうしても必要な場合は **super_admin に問い合わせ** → 個別判断で対応 (super_admin の手動 SQL 経由)

### Expert ↔ Pro の即時切替

- per-call 単価が違うだけなので、月途中切替で同月の課金に単価が混在しても会計上問題なし
- 切替時点以降の API 呼び出しから新単価が適用される

## Consequences

### Positive
- **Beginner プランの「無料枠 100 回」が悪用されない**: 上位プランから戻す抜け道が塞がれているため、Beginner は純粋に「最初の試用期間」として機能する
- **Expert プランのビジネス価値が保たれる**: 「使った分だけ課金、上限なし」が真の意味で従量課金として成立
- **収益予測の安定化**: テナント単位の月次課金額が「プラン × 利用量」で素直に計算可能。ダウングレード予約による予測ブレが発生しない
- **ルールが単純**: 「上にだけ動ける」というシンプルな規則で UI / 実装 / ユーザ説明が容易

### Negative / Trade-off
- **「ちょっと使ってみたい」ニーズへの対応力低下**: 一度 Expert にした後で「やっぱり Beginner で十分」と思っても戻せない。例外パスとして super_admin 経由が必要
- **テナント解約の選択肢を実質的に増やす**: Beginner に戻したい = 利用を縮小したい、というニーズは存在する。これに「解約 → 新規テナント作成」で対応するのは UX として劣る
- **super_admin への問い合わせ運用負荷**: 例外ダウングレード要望が頻発すると 1 人運用 (teppei) の負荷増
- **競合との比較で不利になる可能性**: 一般的な SaaS は柔軟なプラン切替を提供しているため、本ルールは「窮屈」と感じられるリスク

### Risk / 留意事項
- **「テナント一時停止」機能の整備が必要**: Beginner にダウングレードできない代わりに、「数ヶ月使わないので一時停止 → 再開」のニーズに対応する必要あり (現状は機能未実装、将来検討)
- **解約 → 再加入のループに対する制御**: 「解約して新規アカウント作って Beginner で使い直す」が悪用抜け道になる可能性。**同一の代表メールアドレス / 法人番号での再加入は一定期間制限する**等の運用ルールを将来検討
- **法人 / 個人の利用パターン違い**: 法人ユーザは長期契約、個人ユーザは月単位の柔軟性を求めがち。個人ユーザ獲得時に再評価
- **本ルール変更時の影響範囲**: 後から「やっぱりダウングレード許可」に方針転換する場合、過去テナントへの遡及適用判断が必要

## Alternatives Considered

### Alt-1: 自由なダウングレード許可 (一般的な SaaS ルール)
- 概要: Beginner / Expert / Pro 間で自由に切替可能
- メリット: UX が柔軟、競合と同等
- 不採用理由: 上記 Context の悪用シナリオが発生するため。本サービスは Beginner に「月 100 回無料」という大きな無料枠を持たせている特性上、悪用抑止が必須

### Alt-2: ダウングレードは翌月から適用 (即時不可)
- 概要: Beginner ダウングレード予約は受け付けるが、翌月 1 日から有効化
- メリット: 当月の Expert 課金は確定するため悪用部分的防止
- 不採用理由: 翌月 1 日以降はやはり Beginner の無料枠 100 回がリセットされるため、月次ループ悪用は防げない

### Alt-3: ダウングレード手数料 (¥3,000 / 回)
- 概要: ダウングレードは可能だが手数料を徴収
- メリット: 経済的インセンティブで悪用を抑制
- 不採用理由: (1) ユーザ体験が悪い (「逃がさない」感) (2) Stripe / 請求書発行ロジックが複雑化 (3) 個人ユーザの本来の解約自由が阻害される

### Alt-4: 「Beginner の無料枠を月途中切替時にプロラタ計算」
- 概要: Expert→Beginner ダウングレードしたら、当月残日数の割合だけ無料枠を付与
- メリット: 数学的に公平
- 不採用理由: (1) 計算ロジックが複雑 (2) 月途中切替を頻発させる動機をユーザに与え、運用が煩雑化
